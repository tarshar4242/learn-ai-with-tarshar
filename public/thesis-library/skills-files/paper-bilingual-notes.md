# 論文中英對照與研讀摘要

依 GitHub 原版 `paper-bilingual-notes` 的雙交付物執行。原始版本、來源提交與保留原則見 [references/原始來源.md](references/原始來源.md)。不要改動或取代原流程；若使用者想先回答再被追問，改用 `paper-active-reading` 或 `say-then-refine`。

## 交付物

1. **中英對照 `.docx`**：保留英文段落、圖片、圖說、表格與參考文獻位置；每個英文段落後接中文譯文，以清楚可辨的注釋樣式呈現。
2. **研讀摘要 `.docx`**：用 Tarshar 讀得懂、能拿去開會的口語條列，說清楚問題意識、前人研究、核心貢獻、方法、比較、限制與帶走重點。

## 執行

1. 先讀取適用的 PDF 與文件處理指引，再擷取論文的文字、圖片、圖說、表格、頁碼與章節結構。
2. 先建立術語表。作者自定義概念首次出現時保留英文並加中文說明；縮寫、模型名稱與專有名詞維持一致。
3. 逐段翻譯。保留原文的保守程度，例如 `may`、`could`、`suggests` 不可譯成斷言；不虛構原文沒有的研究結果、法規或因果關係。
4. 產出中英對照檔。英文原文不得被改寫，中文緊接對應段落；圖表必須保留在相對應內容附近，複雜表格以可讀性優先處理。
5. 產出口語研讀摘要。以「這篇為什麼值得看、它到底提出什麼、證據是什麼、和我研究有何關係、我還要核對什麼」的順序組織。
6. 在交付前實際檢查 Word 或 PDF 預覽：段落對應、圖表與圖說、術語一致、中文沒有漏段、參考文獻保持原樣。

## 輸出與邊界

- 預設存至使用者指定的論文專案；未指定時先詢問或存草稿，勿自行公開、推送或部署。
- 只使用使用者提供或授權讀取的論文與附件。
- 翻譯檔與摘要檔分開交付，不以摘要取代雙語對照。
- 不能可靠辨識的掃描頁、公式或圖表，要標示待核對，不猜內容。
