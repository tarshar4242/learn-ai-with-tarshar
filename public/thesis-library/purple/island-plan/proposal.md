## 模型如何分工

| 工作 | 推薦角色或模型 | 選擇理由與界線 |
|---|---|---|
| 造島介面與一般實作 | 茜茜 Claude Sonnet 5.5 | 本輪已實際呼叫成功；適合作為一般程式工作起點，並非已測得造島品質第一 |
| 資料契約、串接、測試與整合 | Codex；困難問題用目前可用 Astra | 依工作難度分配；小型明確修改才交較輕模型，不額外堆一群常駐代理 |
| 難解的設計或架構問題 | Claude Opus 或 Astra | 一般模型有根據修正仍卡關時才升級；先核對帳號可用版本 |
| 島的渲染與進度呈現 | 不需語言模型 | Three.js 與有來源的快照即可；雲、海水、小人不應消耗生成 API |
| 現行 B 組問答 | 維持 gpt-5.4-mini-2026-03-17 | 這是暫用基準，未證明最佳；不因造島更動研究引擎 |
| 檢索與字面查找 | 本機 BGE／A 原字串查找 | 保留既有固定版本；A 不需要語言模型 |

本輪 Claude 實際回報模型為 claude-sonnet-5-5。OpenAI 官方建議以同樣輸入比較模型、保留達標的較輕設定；Anthropic 的 Claude Code 指南推薦 Sonnet 處理多數程式工作，Opus 處理困難架構或除錯。這些是選型起點，不是本案品質實測。[1][2]

目前 Codex 工具列出的可委派模型為 gpt-6-astra 及 gpt-5.6-sol／terra／luna；官方網站的模型目錄可能更廣，不能當成此帳號全都可用。本輪沒有修改任何帳號預設模型。

### 真正挑出適合妳的 B 組模型

先比較現行 mini 與已確認可用的 Claude Sonnet 候選，不擴大成全市場競賽。若日後做測試，要確認 API 端可用模型與固定 ID；Claude Code 成功不代表 API 帳號已開通相同模型。

用 20 題開發題，含直接查找、生活口語、模糊條件、多項需求、前文追問、資料庫未收錄等類型。不要抽正式保留題來挑模型。每模型每題做兩次，先固定來源片段比較生成，再對最有希望的方案測完整改寫、檢索與回答流程。後者的模型呼叫數可能多於問答次數。

20 題須在看結果前凍結，記錄出題者，避免與正式題及其改寫重疊。兩模型各跑兩次共 80 筆生成結果；先分成每次 10 筆的人工核對批次，再決定是否擴至完整流程。

人工遮住模型名稱並打亂順序，核對事實、引用支持、回答完整、必要釐清與誠實拒答；另記回應時間及實際 tokens／成本。編造來源或重大錯答需單列失敗，不用平均分掩蓋。先定可接受品質，再選較快、較省者。AI 可以協助挑出疑點，不能代替人工標準答案與正式抽核。[3]

100 美元是本人告知的 Claude API 資源，非已核實餘額。本輪只完成 CLI 評估，未動用研究平台做選型測試；CLI 的列表價成本不等於 API 餘額扣款。未估算整座島的實際建置費用。

## 架構與真實進度

資料流：共同大腦與紫區程式的固定版本 → 白名單快照 → 五島畫面。未來經刪敏的實際執行事件 → 唯讀事件轉接層 → 實驗島。島只是入口與呈現，不另外複製論文正本。

| 畫面層 | 真實來源 | 畫面應說清楚 |
|---|---|---|
| 景觀 | 程式動畫 | 日夜與走路是裝飾，不代表工作正在執行 |
| 研究進度 | vault 固定 commit、文件與人工確認狀態 | 更新時間、來源、版本、待確認；無依據不填完成百分比 |
| AI 運作 | 後端事件與 run ID | 何時開始、改寫完成、檢索完成、回答完成、失敗；沒有事件就顯示未接通 |

看到 AI 運作，是看到可觀測的輸入、階段、結果和引用，不是取得模型私密思考鏈。第二階段才接實際事件；首版可用明標「示意」的重播教學流程。動畫時計與研究紀錄時間分開。

快照生成前檢查欄位與內容，排除不必要全文、未經整理的查詢內容、個資及敏感值。私人入口須 iPhone 已連原有 Tailscale；若連不上，告知檢查私人網路及 Mac 服務。若整個內網頁無法載入，說明需另放在使用者可存取的操作文件，不能依賴失聯頁自己顯示。

快照最少欄位：schemaVersion、generatedAt、sourceCommits、visibility、islands。每筆項目有 id、title、status、sourceUrl、sourceRevision、updatedAt、verifiedBy、nextAction、model（3D 造型種類）。語言模型另放 runtimeModel，避免和建物 model 混淆。未讀、AI 整理、本人核對、教授確認是不同狀態。

本輪建議：每次研究成果已驗證並合併正本後重建快照；載入時標時間，超過 24 小時標「非即時快照」，這是新提案而非已設定排程。異常或中斷保留最後成功版本，但要顯示過期／連線狀態。

## 如何改寫參考提示詞

保留：3D 黏土風、六角島、固定種子、DATA 驅動、柔和色塊、橋、點選卡片、日夜選擇及手機 bottom sheet。

改為：五座研究功能島；每島先放少量有用途的建物。數字由真實資料帶入，未知留空，不把虛構的 50 個政策細項換成 50 個假論文成果。協作線區分「資料依賴」「有紀錄的交班」「示意流程」，不使用 official 標籤暗示政府或學術認證。

分階段：

1. 可執行骨架：五島、相機、水、光、橋、名稱；同資料清單先可用。CDN／WebGL 失敗仍有內容。
2. 研究入口：接白名單快照、點選卡、來源與下一步，連既有紫區平台及架構圖。按鈕用「進入 A/B 實驗」，不能誤稱「問我的論文」。
3. 黏土細節：少量建物零件共用、樹、書、燈、桌椅；遠距離隱藏小物件。日夜可切，減少動態偏好時凍結。
4. 實際事件：另接唯讀事件轉接層；真實 run 與示意動畫可辨，不為畫面改寫研究程序。
5. 驗收：桌面及 390×844 手機尺寸、iPhone 真機、鍵盤、失敗回退、來源與權限。先交可用階段，再擴充小人與景觀。

單一 HTML 適合原型；正式私人版可拆開資料與渲染方便維護，並將 Three.js 固定版本存於本機服務，降低 CDN 失敗影響。前端不得放 API key。初始化要用可捕捉錯誤的動態 import；靜態 import 在執行前失敗，不能只靠內層 try/catch。

原提示詞的 20–30 draw calls 應視為靜態零件庫預算，不宣稱含陰影、水、線、標籤的全場景一定達到。動態 import 的錯誤處理依 MDN 說明。[5] 手機先訂 30 FPS 的試驗目標，實測後才談通過。首次不載入數千棵樹、不強迫 144 秒日夜輪轉。

## 協作結論與後續

Codex 初案六島；Claude 建議合併方法與實驗，採五島。Claude 建議先 2D，Codex 依本人參考保留精簡 3D，附同資料清單回退。Claude 原建議從正式題庫取題選型，Codex 修正為獨立開發題，保留正式測試。兩端原始意見與覆核摘要另存協作紀錄，這些是提案而非教授核准方法。

建議先在原私人服務做五島原型與真實來源卡，設計文件同步公開網站，第一個驗收動作是：手機點「章節書房」能開到紫區第三章，點「實驗島」能進現有 A/B 平台。本輪只同步設計文件，未部署島嶼程式、替換模型或變更研究條件。
