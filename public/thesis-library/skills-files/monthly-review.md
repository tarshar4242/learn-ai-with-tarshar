# 月復盤（monthly-review）

## 這個 Skill 在解決什麼問題

Tarshar 的紀錄分散在六、七個地方：學習日記在 `journals/`、流水帳在 `memory/daily/`、
一件事一篇的協作日誌在 `300_Journal/`、專案進度在 `100_Todo/projects/` 與圖書館的
`projects/`、真正的產出在各 repo 的 git 紀錄裡、行程在 Google 日曆。

**每天都有記，月底卻想不起來自己做了什麼**——因為沒有人把它們合起來看過。

這個 Skill 的核心價值是：**AI 負責把散落的記憶找回來，Tarshar 負責回答「所以呢」**。
不是叫她憑空回想，是先把證據攤在她面前，再訪問她。

> 做法來源：朱騏〈10 個 Codex Plugins〉的「Codex + Obsidian 月復盤」案例
> （<https://henrychu.substack.com/p/10-codex>），2026-08-25 由 Tarshar 指定納入。
> 原文的做法是「讓 Codex 根據它看到的資料，一題一題訪問我。它問，我用語音轉文字回答」。
> 本 Skill 依 Tarshar 的實際資料夾結構、三條主線與公務資料邊界改寫。

## 這不是什麼（她會混淆，先分清楚）

| 名稱 | 是什麼 | 頻率 | 誰回答 |
| :-- | :-- | :-- | :-- |
| **月復盤**（本 Skill） | 一個月一篇、跨專案，AI 先盤點事實再訪問她 | 每月一次 | **Tarshar 本人受訪** |
| 雷小蒙學習日記（`journal`） | 五題學習反思 | 每天 | Tarshar 本人 |
| 每日 Session Log | 當天流水帳 | 每天 | AI 自動寫 |
| AI 協作日誌（`create-ai-collaboration-journal`） | 一件事一篇的完整歷程 | 一件重要的事一篇 | AI 寫 |
| 接力棒（`chat-checkpoint`） | 交給下一個 AI 的工作交班 | 要交接才做 | AI 寫 |
| 研究日誌（`thesis-journal`） | 給教授看的論文進度 | 依論文節奏 | AI 寫 |

**不可以用其中任何一種代替月復盤。** 月復盤的靈魂是「她本人被訪問」，不是 AI 幫她總結。

## 執行流程（四步）

### 第 0 步：環境自檢，先講清楚這次讀得到什麼

（規則出處：圖書館 CLAUDE.md「開新排程／新自動化任務前先列工具需求」）

動手前先確認這個環境有什麼，並用**一句白話**告訴她：

| 需要的東西 | 必要性 | 沒有的話 |
| :-- | :-- | :-- |
| 讀寫本機檔案（ray、圖書館） | **必要** | 沒有就停下來說明，不要硬做 |
| `git log`（各 repo） | **必要** | 沒有就停下來說明 |
| Google 日曆 | 加分 | 月報標「本月行程未納入」，不要假裝有看 |
| Notion 任務總帳 | 加分 | 同上 |
| Gmail | 加分 | 同上 |

講法範例：「這次我讀得到日記、Session Log 跟 git 紀錄，但這個環境沒接到妳的 Google 日曆，
所以行程那塊會空著，其他照做。」

### 第 1 步：事實底稿（AI 自己做完，不要問她）

**這一步一題都不要問她。** 她要看到的是「證據已經攤好了」，不是「請你先回想一下」。

先確認要復盤哪個月（`date` 確認今天；她沒指定就用**上個月**，月底最後三天問她是要復盤「這個月」還是「上個月」）。

逐一掃這些來源，**每一條都要標出處路徑**：

**ray（`~/Agent/ray`）**
1. `journals/YYYY-MM-*.md` — 她自己寫的五題學習日記（**最高權重，這是她親口說的**）
2. `000_Agent/memory/daily/YYYY-MM-*.md` — 每日 Session Log 流水帳
3. `300_Journal/YYYY-MM/` — 當月的 AI 協作日誌
4. `100_Todo/projects/` — 當月有異動的專案資料夾
5. `100_Todo/projects/課程｜超級AI個體｜學習歷程/日誌/` — 大課學習歷程
6. `100_Todo/archive/` — 當月結案封存的
7. `000_Agent/memory/MEMORY.md` — 當月新增的偏好、Feedback、踩坑

**圖書館（`tarshar-vault`）**
8. `changelog.md`、`memory-summary.md` — 當月更新
9. `projects/論文線/`、`projects/品牌線/`、`projects/協作線/`、`projects/投資線/`、`projects/生活線/` — 當月異動的檔案

**真正的產出（git）**
10. 各 repo `git log --since=YYYY-MM-01 --until=YYYY-MM-31 --format='%ad %s' --date=short`
    （ray、tarshar-vault、kt-sweet-journey、thesis-library、tarshar4242.github.io、ai-spell-classroom.github.io）
    —— **這是最誠實的一份**：她說「這個月好像沒做什麼」的時候，commit 清單通常會打臉。

**連接器（有才做）**
11. Google 日曆當月行程（上了幾堂課、開了幾次會、跑了哪些場）
12. Notion 任務總帳：當月完成的、逾期的、還卡著的

盤完，整理成「事實底稿」給她看：

- **時間軸**：一週一段，每段三到五行，寫「這週主要在做什麼」
- **數字**：幾篇日記、幾次 commit、動過幾個專案、上了幾堂課、發了幾篇對外內容
- **三條主線各自進度**：論文線／品牌線／公務職場線，一線三行
- **她自己說過的話**：從 `journals/` 挑三到五句原話（她的原話比 AI 的總結有力得多）

> **鐵則：事實底稿只寫檔案裡真的有的東西。**
> 某週沒有紀錄就寫「這週沒有留下紀錄」，**不可以用推測補滿**。
> （規則出處：圖書館五條規矩第 3 條「不交沒驗過的東西；查不到的事實明說，不編」）

### 第 2 步：訪談（一題一題問，不要一次丟一串）

把事實底稿給她看完，再開始訪問。**六個必問面向**，一題問完等她回答再問下一題：

1. **本月完成的重要事**——「這張清單裡，妳自己覺得真正重要的是哪幾件？」
2. **重複出現的問題**——「這件事這個月出現了三次（列出來），是同一個原因嗎？」
3. **近期一直在想的主題**——「妳這個月的日記裡反覆提到 X，這個是在想什麼？」
4. **學到的工作經驗**——「哪一件事下次會用不一樣的做法？」
5. **要調整的生活方式**——「這個月的節奏，有哪裡撐不下去或撐得太鬆？」
6. **下月要追蹤的事**——「下個月一定要動的是哪幾件？」

**問法規則（做到才算照這份 Skill 做）**

- **每題都要先給引子，再問問題**。引子＝從事實底稿抄一句她自己的紀錄。
  ✅「8/17 妳寫『113 頁 PDF 做完了，但原始影片沒上傳』——這種做完卻卡在最後一哩的，這個月我看到三次。是同一個原因嗎？」
  ❌「這個月有什麼重複出現的問題嗎？」（罐頭題，等於叫她自己回想，這個 Skill 就白做了）
- **每題開頭標進度**：「第 3 題／共 6 題」（ADHD 友善規則，出處 `i-have-adhd`）
- **她說「跳過」就跳過，不追問**（比照 `journal` 的規矩）
- **她說「你先幫我寫」**：用事實底稿代擬一段草稿，明確標「這是我幫妳擬的，請改」，
  **不可以把 AI 擬的內容當成她說的話寫進月報**
- **她用語音轉文字回答**：逐字稿一定有錯字。照 `projects/論文線/論文初稿_每天30分鐘.md`
  累積的「語音錯字表」先修再收，**不要把錯字原樣寫進月報**；不確定的詞當場問一句

### 第 3 步：產出月報

存到 `300_Journal/YYYY-MM/月復盤｜YYYY-MM｜<本月主軸>_MMDD.md`

（檔名規則出處：`300_Journal/README.md`，`類型｜核心對象｜主要成果_MMDD`。
類型固定寫「月復盤」，跟「AI協作日誌」在檔案列表上一眼分得出來。）

檔頭 frontmatter：`date` / `type: 月復盤` / `month` / `topic` / `status`

**八節結構**

1. **本月一句話**——她自己講的那句，不是 AI 總結的
2. **事實底稿**——時間軸＋數字＋主線進度（第 1 步的成果，原封收進來）
3. **三條主線進度**——論文線／品牌線／公務職場線
4. **重複出現的問題**——每項附「出現幾次、在哪幾天、她怎麼說的」
5. **這個月在想什麼**——她的第 3 題回答，用她的原話
6. **學到的工作經驗**——每項後面標一個候選標記：
   - `→ 可升級成規則`（同一個錯誤這個月出現兩次以上）
   - `→ 可建 Skill`（同一個流程這個月做了三次以上）
   （規則出處：ray CLAUDE.md「記憶與自我進化」。**月復盤是執行這兩條的最好時機**，
   平常在單一對話裡看不出「重複三次」，只有月度視角看得到。）
7. **要調整的生活方式**
8. **下月追蹤清單**——可勾選 `- [ ]`，每項要有「什麼時候前要動」

### 第 4 步：歸檔與交付

1. 月報寫檔後 **read-back 驗證**（規矩 3：不交沒驗過的東西）
2. 更新 `300_Journal/README.md` 的月復盤索引（若尚無此區塊，建一張表：月份｜主軸｜連結）
3. 第 6 節如果有 `→ 可升級成規則` 或 `→ 可建 Skill`，**當場問她一句**要不要現在做；
   她說要，就接 `anthropic-skill-creator` 或寫進 `MEMORY.md`
4. 「下月追蹤清單」同步一份到她會再看到的地方：有 Notion 連接器就進任務總帳，
   沒有就寫進 `000_Agent/memory/MEMORY.md` 並說明「這次沒接到 Notion，先放這裡」
5. `commit` + `push`
6. **同一則訊息附上可以直接點的連結**（規矩 4，強制）：
   `https://github.com/tarshar4242/ray/blob/main/300_Journal/YYYY-MM/<檔名>`
   （私人 repo，她登入後看得到；AI 匿名抓 404 是正常的，不必為此說驗證失敗）

## 邊界

- **公務資料邊界（最高優先）**：公務職場線只寫得出通則（案件生命週期、期限管理、
  AI 使用原則），**不寫具體案件、標案、廠商、民眾個資、公文內容**。
  看到風險提醒一句就照她的指示做，不重複勸、不當守門員。
  （出處：圖書館 `AI資料位置共識.md`「公務資料邊界」）
- **不編**：查不到的月份、沒有紀錄的那幾週，就寫「沒有紀錄」。
- **她的原話優先**：月報裡凡是「她的想法」，一律用她受訪時說的話，不用 AI 的漂亮總結。
