# 一頁式報告（one-page-report）

## 這個 Skill 什麼時候用

內容同時符合這三個條件就適用：
1. **多個項目**（工具清單、宣稱、方案、來源…至少 5 項以上）
2. **每項有一句話結論**（對／錯／要注意）
3. **有嚴重度或評級**（高中低、可用不可用、推薦不推薦）

最適合的類別（依合適度排序）：
- 事實查核／來源驗證報告（原生用途）
- 工具或方案的比較選型（例：五個平台選哪個）
- 專案體檢／進度總控回顧（哪些卡住、哪些正常）
- AI 快報的「深度查核版」單期

**不適合**：敘事型心得文、線性的逐步教學、單一主題短文——這些硬套會變得很空。

## 版型骨架（九段，各段之間放分隔線）

1. **開場三行卡**（有色標註框）：日期｜方法｜結果數字（例：「10 項宣稱：3 高嚴重、4 需更正、3 正確」）。方法那行要寫「怎麼查的」，這是全頁可信度的來源。
2. **目錄**：自動目錄（Notion `/目錄`；HTML 用錨點清單）。這就是讀者的「首頁」。
3. **總覽表**：一項一列，欄位＝結論一句話｜嚴重度；嚴重列塗紅底、正確列塗綠底。
4. **詳述**：**只展開高嚴重度的項目**，引用原文證據（引言或程式碼區塊）。其他項停在總覽表就好。
5. **對照表**：需要決策的維度做比較表（例：授權條款、價格、限制）。
6. **修正後清單**：乾淨的「正確版」，用左右雙欄卡片排。
7. **可複製範本**：長範本、提示詞、逐字內容用**折疊標題**收起來。
8. **行動方案**：「這週可做的 N 步」，最好配一張流程圖。
9. **來源清單**：每項附可點連結。之後若有作者觀點，另立一節放最後，**事實與觀點分開**。

## 五色語意表（全頁死守，表格、標註框、圖解通用）

- 🔴 紅底＝高嚴重度／危險／不可以
- 🟠 橘底＝警告／有條件／要注意條款
- 🟢 綠底＝正確／安全路徑／推薦
- 🔵 藍底＝說明／補充脈絡
- 🟣 紫底＝結論／重點提示

## 圖解規則

- 流程圖、決策樹用 Mermaid（深色主題），節點顏色沿用五色語意。
- **每張圖下面必附一行「> 圖說：…」**，把圖翻譯成一句話。

## 執行流程

1. 先把素材整理成「項目｜一句話結論｜嚴重度｜證據連結」四欄清單，給 Tarshar 或自行確認評級。
2. 依上面骨架產出。輸出格式依她指定：
   - **Notion 頁**：用 Notion 工具建頁（callout、table_of_contents、simple table、toggle heading、column、code+Mermaid）。
   - **Markdown**：進圖書館的版本，折疊用 `<details><summary>`。
   - **單檔 HTML**：照 kt-sweet-journey 網頁慣例（繁中、手機優先、單檔）。
3. 交付前檢查清單：
   - [ ] 開場卡三行齊全（日期／方法／數字）
   - [ ] 總覽表每列都有一句話結論＋嚴重度上色
   - [ ] 只有嚴重項被展開詳述
   - [ ] 長內容都收進折疊
   - [ ] 每張圖有圖說
   - [ ] 來源每項有連結
   - [ ] 事實與觀點分開兩區
4. 照圖書館規矩：存檔 → 更新 README 索引 → commit → push → 同一則訊息附連結。
