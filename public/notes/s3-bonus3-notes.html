把用過就丟的提示詞，變成一直幫你做事的專案

益師傅自己說這堂「都是簡單的運用」，但整堂真正在教的是一個很少人做的動作：把你每次都要重打一遍的長提示詞，固定成一個專案，以後只丟檔案就有結果。上半場用會議紀錄套版把觀念做成肌肉記憶，六個步驟做完一個專案，再把同一招原封不動搬到 Gemini 寶石；中場講一件關鍵事：提示詞要寫到連版型與配色都指定，再用一句「注意：請參考資料來源中的檔案」把範例圖釘死。下半場整個進實機，用 FinMind 的免費 API 做出台股 18 格儀表板專案，並且老實比較專案版與獨立程式版哪個準。最後是三種布網方式、Google Sites 當場被 CORS 擋下來的實況，以及他自製的 WASM 網頁加密 Skill。本頁依全程逐字稿與關鍵畫面整理，重點段落附時間碼。

CONCEPT

3. 為什麼要有專案：提示詞不要用完就丟

這一段是整堂的地基。他問的問題很生活：你在職場上是不是常常有同一套提示詞要一直重打？

他說這個概念他 2024 年 10 月就提過

他在課堂上明確講了時間點：2024 年 10 月，在他自己的社團裡提出「提示詞重複利用」的技巧。他說那時候還沒有專案這個功能。

📌
逐字稿把社團名稱聽成「NQTT 社團」，出現兩次。依他後段自述的物聯網背景（他說「我以前在做物聯網」），這裡幾乎可以確定是 MQTT 社團，但本頁不逕自改字，照實記錄。［06:06、127:52、123:55］

拋棄式 vs 重複利用

他的說法是：我們絕大多數的提示詞都是用過就丟的拋棄式，那有沒有辦法重複利用？他舉的例子是行銷企劃案分析。

  • 一份行銷企劃案分析，裡面有行銷 4P、SWOT，這些分析角度都是固定的。
  • 但要你白紙黑字把這些提示詞完整寫出來，「不可能的事情，記不住」。
  • 既然固定，為什麼不把它做成一個公式？以後只要丟一份 PDF、一篇部落格文章、一本書進去，它就幫你執行同一套分析。

這就是專案在做的事：把那段長提示詞放進指令集，把參考範本放進資料來源，以後只餵材料。

哪個平台最早有

他被問到誰最早做出這個功能，回答得很謹慎：

平台他怎麼說
Perplexity「非常早以前就有這個功能」，以前叫 Space（空間），現在改叫專案
Claude跟 Perplexity「差不多同一個時間點」，硬要分先後他覺得分不出來
ChatGPT後來也有了，就是這堂課的主角
Gemini叫寶石（Gem），他個人覺得「好用多了」
⚠️
他說 Gemini 的寶石要被停掉。「他 10 月多才不見嘛，最近還可以用」。他對這個決定很有意見，說「我覺得它廢掉這個沒有什麼道理」、「這種東西就是非常的棒，為什麼要把它取消掉？沒道理」。這是他在課堂上的說法與時間點，實際狀態請以平台公告為準。［08:55、09:00、31:41］
DISAMBIGUATION

4. 先把三個「專案」分清楚

這是他一開始就特別停下來釐清的事，因為他線下教 Codex 時，很多人把網頁版跟桌面版的東西搞在一起。

名稱是什麼這堂教哪個
ChatGPT 聊天裡的專案網頁版 ChatGPT 左側「專案」，把指令與資料來源綁在一起的資料夾✅ 這堂全部在講這個
Codex 裡的專案工作環境裡的專案，是拿來寫程式、部署的後半段布網時才會用到
GPTs機器人，可以做 API 串接，但要有訂閱才能用❌ 刻意不講，留到問答才回答差異

他不講 GPTs 的理由講得很直接：大家談 ChatGPT 都在談 GPTs，但那個要訂閱才能用，沒訂閱就沒了。專案則是每個人都可以用到的功能，卻能做到跟 GPTs 概念一樣的事。［05:53、16:00 前後］

💡
他也提醒：今天全程講網頁版，不是桌面版。這兩個介面不一樣，跟著做的時候不要拿錯。
HANDS-ON 1

5. 實作一：六個步驟做出「會議紀錄套版」專案

這是整堂最該帶走的東西。目標：以後每個月的會議逐字稿丟進去，都自動變成你們公司那份會議紀錄的格式。

步驟一到六

  1. 建立專案。ChatGPT 左側「專案」旁邊按加號，給它一個名字，例如「會議記錄摘要」，按建立。
  2. 點標題進設定。建好之後點專案標題，才會叫出「專案設定」這個視窗。
  3. 貼指令。在「指令」欄位貼上你的提示詞，然後儲存。這裡他用的是一句話。
  4. 回主畫面加資料來源。切到「資料來源」分頁，按「新增資料來源」，上傳樣式.pdf。
  5. 丟材料。回到對話框，把這次要整理的會議記錄文字.txt 拉進去，送出。
  6. 之後每次只要重複第五步。指令與範本都留在專案裡，不用再貼一次。
✍️
他對自己這句提示詞的自評很有意思。他說「好繞舌喔，這一看就知道是我寫的、人寫的，這絕不是 AI 寫的，AI 寫不會那麼繞舌」，然後補一句：「但是有時候繞舌也不錯啦，我們聽起來覺得不順，但是 AI 他聽得懂。」這句話是在鬆綁很多人的焦慮：提示詞不必寫得漂亮，寫得清楚就好。
💡
範本可以是空白的。他說這個「樣式」可以是一份空白的格式表，也可以直接拿上個月的會議紀錄進去，「讓他來學」。重點不是內容，是段落順序與版型。［21:20］
GOTCHAS

6. 三個會卡住你的眉角

這三件事他都是邊做邊踩到才講的，屬於照著步驟做也會卡的地方。

一、手機與平板點不到專案設定

他講得很明確：不要用平板、不要用手機。在手機或平板上點專案標題的中央「不能點，沒有反應」，要改成點那三個點，專案設定才會出現。用電腦則是直接點標題就好。他直接建議上課時用電腦跟。［23:44、24:00］

二、ChatGPT 專案吃不了音檔

他刻意留了那個 MP3 檔，就是為了示範這件事。

  • 在 ChatGPT 專案裡直接丟音檔請它摘要，做不到。
  • Gemini 與 NotebookLM 可以吃音檔。所以流程要變成：先用 Gemini 把語音轉文字，再把文字丟進 ChatGPT 專案。

三、語音轉文字會多出空白，而且別超過一小時

這是他實際被咬到的坑，抱怨得很生動：

  • 逐字稿不要超過一個鐘頭。超過的話「它可能長度，它可以顯現，是會不夠的」。
  • 字跟字中間會跑出空白。他說這個問題之前修好過，「之前改好它現在怎麼又打回原型了」。
  • 解法很土但有效：把轉出來的文字複製到 ChatGPT，請它「把中間的空白的字給過濾掉」，就乾淨了。他這次示範用的那份 34 KB 逐字稿就是這樣處理出來的。
📌
下載包裡那個檔名叫「已貼上文字_去除空白」的檔案，就是這道工序留下的痕跡。［25:41、25:55、26:00］
VERIFY

7. 驗收：把產出跟樣式.pdf 兩相比對

KEY TECHNIQUE

9. 提示詞要寫到版型與配色，再用一句話把範例釘死

這一節是整堂技術含量最高的地方，也是前後兩個實作的橋樑。他要回答的問題是：為什麼你照同一段提示詞做，每次跑出來的樣子都不一樣？

第一層：把細節寫進提示詞

他說最好的方式，是在提示詞裡直接要求它的格式、樣式、版型。

「假如我們在提示詞裡頭要求到配色、要求到版型、要求到裡頭所有的配件，講清楚的話，他做出來就可以盡可能會達到一致。」
他形容這叫「提示詞的細節度的要求」。［46:15］

第二層：加一句「注意」，把範例圖釘死

光寫字還不夠。他的第二招是在提示詞的最後（或最前面）加一段注意事項，把資料來源裡的那張範例圖變成視覺標準答案。

注意 版型、所有內容及配色請參考資料來源中的檔案

他的理由：「我們就不用依賴平臺的能力幫我畫出那樣的圖表，而是根據提醒他的部分，他去學習。」換句話說，不要祈禱模型今天狀態好，而是給它一張圖照抄。他也提到一個小技巧：把範例檔的檔名直接改成「版型」，提示詞就好寫了。［46:33、48:00］

📍
他順帶講了一個提示詞的位置原則：「提示詞裡頭在最後或最上面是最強的」。所以這句注意要放頭或放尾，不要埋在中間。［46:34］

第三層：連交付標準都寫進去

✅
這份提示詞最值得偷走的其實是最後兩句：「不要只提供程式碼或描述『可以製作』；工具具備且資料足夠時，應完成實際檔案。」「沒有足夠真實資料，就不做看起來像真的分析。」前一句治 AI 的偷懶，後一句治 AI 的幻覺。這兩句不只適用股票，任何要求 AI 產出檔案的提示詞都可以照抄。

他對整件事下的結論，是這堂課的骨幹之一：

「你的提示詞不變，但是因為平臺的進步而讓你的結果會更加的棒。所以提示詞還是重要的。」
同一段話他在 34 分與 108 分各講了一次。意思是：把提示詞寫扎實，平台每升級一次你就白賺一次。［108:08］

10. 實作二：台股 18 格儀表板專案

同一個動作，換一個最硬的題目。這一段他先解決一個前提：資料從哪裡來。

先去 FinMind 申請免費 API Token

他說明為什麼不直接連台灣證券交易所：「直接去連結給他用臺灣證券交易所抓，有時候抓不到。所以用 FinMind 來做，其實效果會比較好。」

  1. 到 FinMind 按登入／註冊，可以用 Google 帳號直接進去。
  2. 登入後「就會莫名其妙給你一個 Token」，一長串，複製起來。
  3. 存檔留著，他說「以後都用得到」。
💰
不用錢。他說「這不用收錢的」，額度他口述是「每小時⋯6000 個，基本上還夠」（這句逐字稿辨識為「每小時上千是6000個」，單位不清楚，本頁不替他補）。他另外給了一個很實際的建議：不要一直查。「因為那張表你可能幾個鐘頭才需要畫一次」，被鎖了就過一兩個鐘頭再畫。［41:28、42:15］

建立專案，順手把 ECF 換成自己的名字

做法跟第一個實作一模一樣：按加號、命名（例如「台股個股分析圖表」）、點標題、把 4,700 字的長提示詞貼進指令。

輸入格式不是只丟代號

這是他特別停下來強調的：「抱歉，你這樣 run 一定會有問題的」，因為沒給 Token，它抓到的都是空的，只會畫一張示意圖給你。

8358 金居 FinMind API Key：（貼上你自己的 Token）
  • 代號加空格加名稱，兩個都要給。
  • 附上你自己的 API Key。他在課堂上強調「貼你的喔，不要用益師傅的」。
  • 模型一定要選 GPT-6 Astra。他說「你沒有用 GPT-6 的 Astra 跑起來，就是怪怪的」，還建議把推理強度開到最高，因為 18 個區塊要做的事很多。
🔒
本頁沒有收那一張輸入畫面的截圖。他示範時把自己的 FinMind Token 整串明碼秀在螢幕上，那是憑證，不適合留在網頁上。這裡改用文字示意格式。你自己在用的時候也一樣：Token 貼在對話框裡就好，不要寫進提示詞檔案、不要放進會分享出去的 HTML。這一點他的提示詞第一節其實就寫明了。
BEHIND THE SCENES

11. 他怎麼一步步把這個專案磨出來

有學員問他「你那數字到底怎麼抓的」，他說「我不相信這樣講一講就懂了啦」，然後把自己的對話紀錄整個打開給大家看。這一段是全堂最有價值的部分：不是成品，是過程。

他的五個回合

  1. 先給舊提示詞。拿以前那支個股分析提示詞，請 AI 先做一次。「他就開始幫我做，然後我給他幾個代號，他幫我做。」
  2. 不滿意，就給一張目標圖。做出來的圖表他不喜歡，於是直接丟一張範例：「我要的是這張圖表」。他說「做這樣就是 Bingo 了，這代表對囉」。
  3. 要真資料，不要 Copy。他發現內容是抄來的、是空的，就一步步跟它確認：「這些都是空的，都不是真的，我就跟他講，我要有實際的資料。日期應該這樣子。」
  4. 要求串接 FinMind。把資料來源定死，讓它去真的取數。
  5. 加上 ECF 浮水印。理由很務實，見下面。
🔑
關鍵在第二步。他自己點破：「關鍵是我原本用舊的提示詞給了他，但是我又給他一個新的表格，他從這裡頭去幫我做。」舊提示詞負責邏輯，新範例圖負責外觀，兩個分開餵，就不用重寫幾千字。這跟第九節那句「請參考資料來源中的檔案」是同一個道理，只是一個用在對話裡、一個固定進專案。［59:38］

為什麼要加浮水印

他講得很白：程式會流傳出去，「我也不曉得會流傳到哪裡去」。訂閱制的東西如果別人也能用，對付錢的人不公平，所以上面要寫個 ECF。但他馬上補了一句，把門又打開：

「可是我把程式碼給你們了，換句話說，你就有能力可以改成不要 ECF。」
他的邏輯是：我用浮水印擋外流，但給你原始碼讓你換成自己的名字。［60:59］

12. 專案版 vs 獨立程式版，哪個準

這是他這堂課給得最誠實的一段。同一件事他做了三個版本，然後直接講哪個好、為什麼。

版本優點限制
ChatGPT 專案版不用寫程式，人人可做；他說在專案裡能畫成這樣「難度就比較高」，算誇張沒那麼好看，純文字比較多；只能用基本繪圖能力，叫不動外部工具；常常抓不到資料
ChatGPT 獨立程式版準確度高、可下載 PNG他說它「就是很柔性，對比色不是那麼強烈」；而且當場發現這支不是單一檔案，是 HTML 加 CSS 分開的包覆檔，所以沒直接發

他的結論講了兩次，立場一致：

［54:00］到了問答時間他又說了一次：「我個人認為要精準的話還是要寫成一個獨立的程式會比專案來得好」，但補上程式版的代價：你不在 ChatGPT 平台裡，所有 API 要自己張羅，用 OpenAI 要錢，用免費的 Groq API 又有流量限制。［107:07］

他當場驗了數字

對完之後他說「真的啊，這數字一模一樣啊，我檢查過了，這寫的有夠準的」。［69:19、69:31］

DEPLOY

13. 布網三法，以及當場被擋下來的那一次

有學員說「我想要自己做可不可以」，他就把布網也教了。這一段含金量很高，因為包含一次真實的失敗。

方法一：Codex 加 @Sites

最省事的做法。把程式檔拉進 Codex，然後叫出 @Sites 這個功能再下指令。

  • 一定要指定 @Sites。他提醒「你不用寫這個 Sites 的時候，它會用別的布網的工具」。
  • 一定要說「全線打開」。不打開存取權的話，「連你自己登錄使用的時候，他都要用 ChatGPT 登錄的方式才可以」。
  • 網址可以指定關鍵字。他要求網址要有 ECF，所以他的網址才會長出那三個字。他說「因為被你們偷偷學到了」。

方法二：Site.new（Google Sites）整頁嵌入

給沒有 Codex 的人用的路。他說「最簡單就是 Site New」。

  1. 頁面 → 加號 → 整頁嵌入 → 命名（用英文）→ 完成。
  2. 點「新增整頁嵌入內容」→ 選嵌入程式碼（不是網址）。
  3. 用記事本開啟你的 HTML（右鍵 → 開啟檔案 → 選記事本），Ctrl + A 全選、Ctrl + C 複製，貼進去。
  4. 看預覽有沒有出來。他強調「這個一定要有。假如這個預覽頁面沒有，這代表你 Copy 出了問題」。
  5. 按插入，然後把這個頁面拖到首頁上面讓它變首頁，再按發布。

然後它就當場失敗了

✅
這一段值得慢慢看。失敗之後他沒有跳過，而是當場除錯：先確認連原本的程式單獨跑也不行，判斷是被攔截；接著換另一支程式（那支 101 KB 的 Claude 版）請大家試，成功了。回頭才找到真正原因：剛剛那支 4.83 MB 的是互動式網頁，不是原本的程式。他的原話是「那個程式才是正常的程式啦」。

這裡的教學價值不在 Google Sites，在於他示範了一個排錯順序：先確認範圍（是這個平台的問題還是程式的問題）→ 換一個已知可用的版本試 → 回頭找出拿錯檔案。［86:42 到 89:23］
💡
方法三其實藏在提示詞裡。那份 4,700 字提示詞的第十一節「交付要求」，本來就要求 AI 直接產出可互動 HTML 與 ZIP。也就是說，你可以完全不碰 Codex 與 Sites，讓專案自己把檔案交出來，再自己找地方放。

15. 問答：GPTs 跟專案到底差在哪

這題他說「這個問題問得很好」，然後花了六分鐘回答。答案比想像中有層次。

差別在「串接」這件事

GPTs專案
能不能串 API可以，裡面能寫 JavaScript 或 Python不能，只能用平台自己的能力去抓
準不準準。因為你明確告訴它去哪裡抓、回傳是什麼格式，「所以我抓到都不會偏差」常常抓不到，「就有剛剛一樣抓不到的問題」
會不會被 CORS 擋比較不會，它是直接去抓會，就是課堂上那一幕
好不好寫難。要把 request 與 response 的規格「瞭解到透徹」，JSON 在第幾層、要抓哪個欄位都要講死容易，用提問的方式就行
要不要訂閱要不用

但他認為 GPTs 正在被時代繞過

理由不是 GPTs 不好，是串接這件事本身變簡單了。他的對照很具體：

  • 以前（GPTs 時代）：要串 Yahoo 天氣預報，得把 request 格式、response 的 JSON 第幾層、要抓哪些欄位，全部寫清楚、要一致、要完整。他說自己最早寫 GPTs 時「很辛苦」。
  • 現在（MCP 時代）：在 Codex 裡「我只要跟他講，我要寄一封 mail、我要串接 Canva、我要串接 Gamma，我只要透過 MCP 的運用，我只要輸入帳號密碼，基本上它幫我串接起來了」。
📌
逐字稿把 MCP 聽成「NCP」，依上下文（他在講 Codex 串接外部服務）判斷是 MCP，本頁照上下文說明但不替他改字。

另一題：能不能排程每天自動存圖

有學員問能不能讓它自動抓資料、存成固定格式的圖檔。他的答案是可以，但不要在對話裡做：

  • 把原本這支程式丟給 Codex、Antigravity 或 Claude Code。
  • 跟它說：把這個程式改成排程，自動抓 2330、2360 這幾檔，每天存成一張 JPG，檔名格式你也可以規範。
  • 他說「這絕對是做得到的，這沒有問題」。
💡
他還提醒一個資料本質的問題：這個分析抓的是當日即時資料，如果你要存圖，本質上就是在自己建立歷史資料庫，要一天一天累積。

還有一題他的回答很適合新手：有人問提示詞要怎麼下。

「不用問提示詞怎麼下，你可以問 AI。」
他的建議是直接問：我要串 Google Sheet，我必須要提供什麼資料給你、應該怎麼處理。「現在的 AI 已經非常非常進步，我們以前都要自己做。」［109:09］

16. 收尾：參照學習算不算侵權

課的最後 10 分鐘，他丟出一個沒有標準答案的問題，還請大家在聊天室留言。這段跟技術無關，但他講得很認真。

他問的問題

如果別人的東西不是放在 GitHub 上分享的，而只是一支影片、一篇文章，我們用 NotebookLM 把它做成自己的心得、做成 15 頁簡報、做成語音材料，這算不算侵權？

他自己先承認：「不 OK，可是我們卻一直在做這個事情，對不對？很難認定吧？」然後他戳破一個常見的說法：

💬
有人回「沒有商用就沒事」，他當場反駁：「這句話有問題啦。」他舉自己的例子：他放一支 YouTube 上去，別人拿去做參照學習，產出的簡報、標題、Banner 都很像，到底可不可以？他也點出真正的雙標：「我們卻可以允許自己去讀別人資料，但是卻不能允許別人來用我們的資料。」［120:30、121:57］

他給的實務界線

「學習可以這麼做啦，你自己學習 OK，但是假如你要發表文章的時候，稍微去留意，稍微去小心一下。」
他的分界是自用與發表：自己學怎麼做都行，一旦要對外發表就要留意。能標註來源當然最好。［124:40］

他也講了心境上的轉變，這段滿有溫度的。他說一開始看到別人抄他的圖表格式會生氣，後來換個角度想：

「換一個角度想，我的東西還有那個價值，人家願意用。」
他還加了一句自我調侃：那些在社群上出現的黑白對比區隔圖，「那一定是抄我的，但是幫你打廣告，換句話講，這樣也算是一個好事吧」。［125:37、125:50］

最後他給的解法

「盡量自己做，別人抄到就是你舊的資料，永遠都是最舊的資料。」
他的意思不是鼓勵被抄，是：你走在前端，被拿走的永遠是你的上一版。［125:00］

不過他也提醒了一個殘酷的現實，這段是回應學員說「抄的人永遠看到車尾燈」：

⚖️
他說不一定，要看抄的人是誰。如果抄的人名聲比較大，大家反而會以為原創是他。「人家永遠就認定這個名聲比較大的人，不是嗎？這樣是不公平的啦⋯⋯就是話語權啦，誰說了算。」那怎麼辦？他的回答是：「你覺得不公平，那就搶回來吧。因為人家看不到你，你就想辦法讓人家看得到你吧。」［126:31、127:29］

整堂課的最後一句是這個：

「學到就是自己的，別人帶不走。」
前一句是「等於說一個功能，三個平臺都可以用，把它學起來」。他提醒 Gemini 的寶石、Claude 的 Project 做法都一樣，學一次通三家。［128:45］
