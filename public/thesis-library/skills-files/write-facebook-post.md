# Facebook 貼文寫作

把使用者提供的真實素材，整理成保留 Tarshar 個人聲音、適合手機閱讀的 Facebook 貼文。先守住事實與情感真實，再處理結構、節奏與文字。

## 開始前

1. 讀取 `references/style-guide.md`。
2. 查看 `200_Reference/writing-samples/facebook/`，依本次類型選讀 2–3 篇最接近的範例。
3. 若使用者提供當次範本、版本或指定格式，優先遵循當次要求；範例只用來校準語氣，不得蓋過明確指示。
4. 確認至少有主題與核心素材。缺少會改變文章方向的資訊時，只問最關鍵的一題；可安全補足的結構細節直接處理。

## 判斷貼文類型

依素材選擇主要結構，可混合但不要硬套：

- 個人生命故事：當下回望 → 具體事件 → 害怕或轉折 → 新理解 → 溫暖收尾。
- 短篇生活感悟：生活小事 → 一個意象或陪伴物 → 兩三層感受 → 輕巧收尾。
- 專業事件分析：數字或事件鉤子 → 個人專業視角 → 分層拆解 → 連回工作／研究 → 可帶走的判斷。
- 親情文化故事：當下驚喜 → 過往記憶 → 時間跨度 → 緣分落點 → 真誠感謝與小幽默。
- 旅行紀錄：意外開場 → 旅伴互動 → 分段亮點 → 實用心得 → 回扣旅程意義。

## 寫作流程

### 1. 整理素材

- 區分「使用者親身經歷」「使用者觀點」「可公開查證的事實」。
- 保留人名、年份、數字、對話、地點與小動作等具體細節。
- 不補寫使用者沒有說過的經歷、情緒、對話、動機或結果。
- 若素材涉及新聞、醫療、法規、價格、日期或其他時效資訊，先查證可靠來源。無法查證時標示待確認，不把推測寫成事實。

### 2. 決定是否先給大綱

- 長篇、專業分析或素材很多：先提出 3 個明確不同的大綱方向，等使用者選擇後再成文。
- 短篇、已有完整結構、使用者提供明確範本，或使用者要求直接完成：直接寫初稿。
- 修改既有貼文：保留原本最有生命力的句子，先修方向與段落，再修字詞。

### 3. 形成文章

- 從具體場景、數字、對話、意外或真實感受開場，不先講大道理。
- 一至三句換行，讓手機閱讀有呼吸；長文可用 `---`、Emoji 小標或 `▍` 分段。
- 讓觀點從故事自然長出來，不用結論壓過故事。
- 專業內容先講人能懂的話，再補名詞；必要時用編號、對照或「一道一道防線」拆解。
- 保留輕微自嘲、家人互動與口語節奏，但不要每段都刻意搞笑。
- Emoji 只做情緒或段落提示。Hashtag 以 3–6 個為原則，除非使用者指定更多。
- 篇幅由內容自然決定：短篇可短、深度故事可長；使用者指定長度時以當次要求為準。

### 4. 自我檢查

交稿前逐項檢查：

- 開頭是否在前三行內讓人知道「發生了什麼」或「為什麼值得讀」？
- 是否至少有一個只能來自使用者的具體細節？
- 每段是否只承擔一個主要意思？
- 轉折是否來自事件本身，而非硬塞金句？
- 刪掉空泛形容詞後，意思是否更清楚？
- 是否出現公關稿、新聞稿、說教或過度煽情語氣？
- 是否捏造任何經歷、數字、對話或情緒？
- Emoji、Hashtag 與行動呼籲是否過量？
- 結尾是否回扣前文，並保留 Tarshar 溫暖、帶點幽默的餘韻？

## 禁用寫法

- 不寫成公關稿或新聞稿。
- 不用「顛覆、革命性、超強、賦能」等空泛詞堆砌 AI 價值。
- 不站在高處教訓讀者，不把個人經驗包裝成唯一答案。
- 不捏造經歷、數字、對話、情緒或公共事件細節。
- 不濫用「不是 X，而是 Y」、三段式排比、長破折號或刪掉也不影響意思的句子。
- 不固定塞入「歡迎留言、分享、按讚」等行動呼籲。
- 不自動發布到 Facebook；任何對外發布都必須由使用者明確要求並再次確認。

## 交付格式

先提供乾淨、可直接複製的貼文正文。只有在有助於決策時，才另外附上：

- 2–3 個開頭替代版。
- 待確認的事實或資料來源。
- 一句話說明採用的結構。

長篇草稿或使用者要求存檔時，存到：

`100_Todo/drafts/facebook/YYYY-MM-DD_簡短主題.md`

不要把分析說明混進可複製的貼文正文。
