單元 ①Pandas 與 SQL 常用操作：合併與分組

為什麼需要這個概念？ 真實資料很少只有一張表：每個月一個檔、客戶資料和訂單資料分開放。分析之前，第一件事就是「把表接起來」或「分組算統計」。Pandas 和 SQL 各有一套工具，名字很像，用途卻不同，最常被拿來混。

一步步搭起來

  1. 先問：兩張表的欄位一樣嗎？一樣（例如 1 月檔、2 月檔都是「日期、產品、金額」），就是把列往下疊，用 concat()。
  2. 欄位不一樣，但有共同的鍵欄位（例如都有「客戶ID」），就是依鍵對接，用 merge()，等於資料庫的 JOIN。
  3. merge 還要決定「留哪些鍵」：參數 how 最常用的是 inner、left、right、outer 四種（另有 cross 等）。沒有指定時，merge 預設 how＝'inner'，join() 預設 how＝'left'。
  4. 接好之後要分組算統計：Pandas 用 groupby() 加聚合方法；SQL 用 GROUP BY，通常搭配聚合函數（SUM、AVG、COUNT、MAX、MIN）。
想做什麼PandasSQL 對應一句話
兩張表依同一個鍵接起來merge()JOIN依鍵欄位橫向對接，how 決定留哪些鍵（預設 inner）
結構相同的檔案接成一個大檔concat()UNION ALL往下堆疊（也可以設定成橫向）
依索引橫向合併join()JOIN預設用索引對接（how 預設 left），不是拿來堆疊的
分組後算每組統計groupby()＋聚合方法GROUP BY＋聚合函數SUM、AVG、COUNT、MAX、MIN；分組後再篩選用 HAVING
選欄位、指定來源表、篩條件df[...]、query()SELECT、FROM、WHERESELECT 選欄位，WHERE 篩列
排序sort_values()ORDER BY排序不是 GROUP BY 的工作
刪除有缺失值的列或欄dropna()WHERE … IS NOT NULL把空值那幾筆拿掉
刪除完全重複的列drop_duplicates()DISTINCT只留一份
看前幾列／最後幾列head(5)／tail(5)LIMIT n（取前 n 筆）；看最後幾筆要寫 ORDER BY 欄位 DESC LIMIT nhead 對應 LIMIT；tail 在 SQL 沒有直接對應，要先反向排序再 LIMIT
易錯提醒：記法是「堆疊用 concat，對照合併用 merge」。concat 不看鍵欄位，只是把表疊在一起；merge 一定要有鍵。join() 雖然也是合併，但預設看的是索引。GROUP BY 通常搭配聚合函數，但不搭配也能執行（效果等同 DISTINCT）；SELECT 裡沒有被聚合的欄位，必須寫進 GROUP BY；分組之後要再篩選，用 HAVING，不是 WHERE。排序要找 ORDER BY，別跟 GROUP BY 配錯。還有，SQL 沒寫 ORDER BY 時不保證回傳順序，所以 LIMIT 取到的「前幾筆」要搭配 ORDER BY 才固定。

單元 ②數據轉換：離散化、對數轉換、縮放與 PCA

為什麼需要這個概念？ 原始資料常常不能直接餵給模型：有的欄位是連續數字但我們想要分組，有的分佈歪得很嚴重，有的欄位數字大小差好幾百倍，有的欄位彼此幾乎在講同一件事。每一種問題有自己的轉換方法，名字聽起來都像「整理數字」，但解決的問題完全不同。

一步步搭起來

  1. 想把連續數字變成幾個類別 → 離散化（分箱）。
  2. 分佈往右拖一條長尾巴 → 對數轉換。
  3. 各欄位的數字範圍差很多 → 標準化或歸一化（只改尺度）。
  4. 欄位彼此高度相關、想減少欄位數 → PCA（主成分分析）。

離散化／分箱：連續數字切成區間

年齡（連續數字）1825385270
分箱後（類別）青年青年中年中年老年

把連續的數值切成有限個區間或類別，叫離散化（Discretization），也叫分箱（Binning）。切完之後資料變成「類別」，不再是連續數字。區間怎麼切由分析目的決定，可以等寬，也可以依人數等分。

對數轉換：專門對付右偏

  • 右偏（正偏態）：多數數值很小，少數特別大，收入、價格、點擊數都很常見。平均數會被少數極大值拉走。
  • 取對數之後：大的數被壓得比較近，長尾縮短，分佈變得比較對稱，有利後續分析與建模。
  • 不適用：本來就對稱的資料不需要；左偏的長尾在另一邊，取對數反而更歪；類別資料不是數字，不能取對數。
  • 小提醒：對數只能用在大於 0 的數；資料裡有 0 時，實務上常改用 log(x＋1)。

標準化、歸一化與 PCA：誰能消除特徵相關？

標準化和歸一化都是「把每個欄位各自換一把尺」。換尺不會改變點與點的相對位置，所以欄位和欄位之間的相關性也不會改變。真正能把相關性拿掉的是 PCA：它把座標軸轉到資料散開最多的方向，得到一組彼此不相關的新特徵（主成分）。不過 PCA 只去除線性相關，非線性的關係它處理不到。

方法做什麼會改變特徵間的相關性嗎？主要用途
標準化 Z-score變成平均 0、標準差 1不會（只改尺度）各欄位尺度差很大時，讓大家站在同一起跑線
歸一化 Min-Max縮到指定範圍，預設 [0, 1]（又稱正規化）不會（只改尺度）對數值範圍有嚴格要求時，例如圖像像素
對數轉換取對數不是用來消除相關的處理右偏
PCA旋轉到新的軸（主成分）會：主成分彼此不相關（相關係數 0）、主軸互相正交；只去除線性相關降維、保留最多變異、去除欄位間的重複資訊
  • PCA 的主要目的是降維，並盡量保留原始資料的變異。主成分彼此不相關，是它附帶的特性。
  • 做 PCA 之前通常先標準化，避免數字範圍特別大的欄位主導整個結果。
  • Min-Max 很怕離群值：只要出現一個特別大的值，其他點就全被擠在一小段裡（圖上的 100 就是例子）。
  • 標準化不會把資料變成常態：它只是平移和縮放，分佈原本歪的，標準化之後一樣歪。
易錯提醒：特徵縮放之後結果仍然是數字；離散化之後才變成類別。獨熱編碼是把「類別」變成好幾個 0／1 欄位，常接在分箱之後使用，但它不會把分箱還原成連續數字。看到「消除特徵之間的線性相關」就想 PCA，不是標準化，也不是歸一化。

單元 ③重複數據怎麼判定

為什麼需要這個概念？ 同一筆訂單被系統記了兩次，營收就會被算多。所以清理資料時要先找出重複。問題是：怎樣才叫「重複」？答案取決於你定義的比對範圍，不能單看它進來的時間，也跟它存在電腦哪裡無關。

一步步搭起來

  1. 先決定比對範圍：比對全部欄位，或只比對你指定的鍵欄位（Key Columns）。
  2. 範圍內的值全部相同，才算重複。
  3. 找到重複後，再決定留哪一筆：留最早的、最新的，或最可靠的那筆，依情境而定。
客戶ID姓名金額時間戳記以「客戶ID＋姓名＋金額」為鍵，是重複嗎？
A1小美8010:00第一筆，作為比較基準
A1小美8010:05重複（以本表選定的鍵來看）：鍵欄位完全相同，時間戳記不在鍵裡
A1小美9010:00不是重複：金額不同，時間一樣也沒用
易錯提醒：時間戳記不能「單獨」當判斷標準：時間相同不代表重複，時間不同也不代表一定不是重複。算不算重複，取決於你定義的比對範圍：比對全部欄位時，時間戳記也在裡面，時間不同就不算重複；鍵欄位只選客戶ID＋姓名＋金額時，時間不同仍算重複。實務上最可靠的鍵，是訂單編號這類唯一識別碼。記憶體位址是電腦內部存放位置，跟資料內容無關；平均值相同也不代表是同一筆。

單元 ④Hadoop 與 Spark 分工：誰存、誰調度、誰運算

為什麼需要這個概念？ 資料大到一台電腦放不下、算不完，就要很多台機器一起合作。合作需要分工：有人負責把資料存好，有人負責分配每台機器的資源、把工作排進去，有人負責真正動手算。考試最愛問「這件事是哪個元件負責的」。

一步步搭起來（由下往上）

  1. 最底層 HDFS：把大檔案切成很多塊，分散存在很多台機器上。
  2. 往上一層 YARN：資源管理與任務調度，決定誰用多少 CPU 和記憶體、工作排到哪台機器執行。
  3. 再往上是運算框架：MapReduce 把運算分成 Map、Shuffle、Reduce 三個階段，以批次方式處理，每個階段的中間結果都寫回磁碟；Spark 把中間結果盡量留在記憶體，再加上 DAG 排程，需要反覆算很多輪的迭代運算（例如機器學習）特別快。記憶體不夠時，Spark 也會把資料寫入磁碟。
  4. 最上層是好用的介面：Hive 讓人用類 SQL 的 HiveQL 查詢大數據，屬於批次查詢、延遲高；Pig 則用 Pig Latin 腳本描述資料處理流程。兩者底下都再交給運算引擎執行。
  5. 注意 Spark 的位置：Spark 可以脫離 Hadoop 獨立部署，也可以跑在 YARN 上、讀 HDFS 的資料。它取代的是 MapReduce，不是 HDFS。
元件負責什麼一句話
HDFS分散式儲存倉庫：把大檔案切塊存在很多台機器上
YARN資源管理與任務調度調度員：分配 CPU、記憶體，安排工作在哪裡跑
MapReduce批次運算模型工人：Map、Shuffle、Reduce 三階段，中間結果寫回磁碟
Spark快速的分散式運算框架工人：中間結果留在記憶體＋DAG 排程；最核心的資料抽象是 RDD；可獨立部署
Hive用類 SQL 的 HiveQL 做批次查詢櫃台：上層介面，延遲高；底下交給 MapReduce 或其他引擎執行
Pig用 Pig Latin 腳本描述資料處理流程另一種上層介面，寫腳本而不是寫 SQL

RDD 是什麼？ RDD 全名是彈性分散式資料集（Resilient Distributed Dataset），是 Spark 最底層、最核心的資料抽象：一份資料被切成很多片，分散在不同機器上，而且壞掉時可以依照記錄的計算步驟重算回來。Spark 的 DataFrame 是建在 RDD 之上、比較好用的高階介面。

RDD 的兩種操作：Transformation 與 Action

對 RDD 下的指令分成兩類。Transformation（轉換）是惰性的：下指令時 Spark 只把步驟記下來，畫成一張 DAG，並不馬上算。Action（動作）一出現，Spark 才照著記下來的步驟真正開始算，並把結果交回來或寫出去。

類型做什麼常見例子什麼時候真的算？
Transformation從一個 RDD 產生新的 RDDmap、filter、flatMap、groupByKey、reduceByKey、join不會馬上算（惰性求值），只記下步驟
Action要一個結果，交回程式或寫出去count、collect、take、first、reduce、saveAsTextFile這時才觸發前面所有步驟一起算
  • 為什麼要惰性？Spark 先看完整條流程，才能把步驟合併、少做白工；記下來的步驟也讓資料壞掉時可以重算回來。
  • 分辨口訣：回傳的還是 RDD，就是 Transformation；回傳一個數字、一份清單，或把檔案寫出去，就是 Action。
易錯提醒：HDFS 管儲存，YARN 管調度，兩個最常被搞混。問「Spark 核心抽象」要答 RDD，不是 DataFrame（它是上層介面），也不是 HDFS（那是儲存系統）或 MapReduce（那是另一套運算框架）。另外小心名字很像的一對：reduce 是 Action，reduceByKey 是 Transformation。

單元 ⑤抽樣與它的鄰居們

為什麼需要這個概念？ 資料有幾億筆時，每次分析都跑全部太慢也太貴。如果能挑出一小部分、又能代表整體，就能用很低的成本得到差不多的結論。這就是抽樣。它常和聚合、整合、標準化擺在一起比較，因為它們都在「處理資料」，但目的完全不同。

一步步搭起來

  1. 目的：降低計算成本，但結論仍要能代表整體。
  2. 做法：從大資料集中選出一部分「代表性子集」，每一筆仍是原本的資料。
  3. 挑選方式：依資料特性選一種抽樣方法（見下表）。
名稱做什麼跟抽樣的差別
數據抽樣從大資料集中選出代表性子集目的：降低計算成本，選出來的仍是原始資料
數據聚合把很多筆算成一個摘要（總和、平均）筆數也變少，但不是「挑一部分」，而是「算出一個數」
數據整合把不同來源的資料合併是增加資訊，不是減少資料量
數據標準化把數值重新量尺資料筆數完全不變
抽樣方式怎麼抽適合情境
簡單隨機抽樣每個個體被抽中的機率相等，而且任何一組 n 筆樣本被抽中的機率也都相同母體很均勻時
分層抽樣先分成子群體（層），每一層都抽，常依比例抽；分層原則是層內相似、層間不同想讓樣本反映各子群體的比例
系統抽樣先隨機選一個起點，之後固定間隔抽一個，例如每 100 筆抽 1 筆資料已排成清單、操作要簡單；清單本身有週期性時要小心，可能每次都抽到同一種
整群抽樣隨機抽出部分群組，抽中的群組全部納入；理想上群內差異大、群間相似資料天然分成很多群，例如分店、班級
易錯提醒：聚合也會讓資料變少，所以最容易和抽樣混淆。分辨方法：抽樣後拿到的是「一部分原始資料」；聚合後拿到的是「算出來的摘要數字」。另外，「每個個體被抽中的機率相等」不是簡單隨機抽樣獨有，系統抽樣也做得到；簡單隨機抽樣多了一個條件：任何一組 n 筆樣本被抽中的機率都相同。分層和整群也別搞反：分層是每一層都抽（層內相似），整群是只抽部分群組、抽中就整群收（群內差異大）。

單元 ⑥資料管線：批次與串流、ETL 與 ELT

為什麼需要這個概念？ 資料不會只處理一次就結束：每天都有新訂單、每秒都有新點擊。要決定「多久算一次」（批次還是串流），也要決定「先整理再放進倉庫，還是先放進去再整理」（ETL 還是 ELT）。這兩組加上一堆工具名稱，最常被拿來考配對。

一步步搭起來

  1. 先問：結果要多即時？隔天看報表就夠 → 批次；要幾秒內反應（例如盜刷偵測）→ 串流。
  2. 串流再分兩種：每隔幾秒切成一小批來算，叫微批次（Spark Streaming）；每一筆一進來就算，叫原生逐筆串流（Flink）。
  3. 資料要有人負責運送：Kafka 像一條輸送帶，負責接收、暫存、傳遞事件，真正的運算交給 Spark 或 Flink。
  4. 資料進倉庫的順序：先轉換再載入叫 ETL；先載入再轉換叫 ELT。
  5. 最後要有人排班：每一步什麼時候跑、照什麼順序跑，交給排程工具，例如 Airflow。

批次 vs 串流

方式怎麼算延遲代表工具
批次收齊一整段資料（例如一天）再一次算完高（小時、天）MapReduce、Spark 批次作業、Hive
微批次每隔幾秒切成一小批，一批一批算中（秒級）Spark Streaming
原生逐筆串流每一筆資料一進來就處理低（毫秒級）Flink
訊息佇列（不是運算）接收、暫存、傳遞事件給下游不適用Kafka

Kafka訊息佇列、事件串流平台輸送帶：把資料送到下游，運算交給 Spark、Flink
易錯提醒：Kafka 最常被誤當成運算引擎。它的本業是接收、暫存、傳遞事件；要算東西，通常接 Spark 或 Flink（Kafka 另有 Kafka Streams 函式庫可做簡單運算，但那是另一個元件）。Spark Streaming 是微批次，Flink 才是原生逐筆串流，兩者別配反。Airflow 管「什麼時候跑」，dbt 管「怎麼轉換」，ETL 和 ELT 只差在 T 和 L 誰先。

總整理本章要記的十六句話

  1. concat 往下疊（結構相同）；merge 依鍵欄位接（像 JOIN）；join 預設用索引。
  2. merge 的 how 最常用四種：inner 只留共同鍵、left／right 以一邊為主、outer 全部都留（另有 cross）；merge 預設 inner，join() 預設 left。
  3. GROUP BY 通常搭配聚合函數（SUM、AVG、COUNT、MAX、MIN）算出各組統計；SELECT 裡沒有被聚合的欄位，必須寫進 GROUP BY；分組之後要再篩選，用 HAVING，不是 WHERE。
  4. SELECT 選欄位、FROM 指定表、WHERE 篩條件、ORDER BY 排序；head 對應 LIMIT，tail 要先 ORDER BY … DESC 再 LIMIT。
  5. 連續數字切成區間或類別＝離散化／分箱。
  6. 對數轉換用在右偏（正偏態）；類別資料不能取對數。
  7. 標準化、歸一化只改尺度，不改相關性；歸一化預設縮到 [0, 1]（很怕離群值），標準化變成平均 0、標準差 1（不會變成常態）。
  8. PCA：降維、保留變異、主成分彼此不相關（只去除線性相關）；做之前通常先標準化。
  9. 重複＝在選定的比對範圍（全部欄位或指定鍵欄位）內，值全部相同；不能只看時間戳記、記憶體位址或平均值。
  10. HDFS 儲存、YARN 資源管理與調度、MapReduce（Map、Shuffle、Reduce，中間結果寫磁碟）／Spark（記憶體＋DAG）運算、Hive 用類 SQL 的 HiveQL 批次查詢；Spark 可獨立部署，取代的是 MapReduce。
  11. Spark 核心抽象＝RDD；DataFrame 是建在它上面的高階介面。
  12. RDD 的 Transformation 是惰性的（map、filter、reduceByKey），遇到 Action（count、collect、reduce）才真的算。
  13. 抽樣＝選代表性子集來降低成本；聚合是算摘要、整合是合併來源。分層每層都抽、整群抽中就整群收、系統抽樣從隨機起點固定間隔抽。
  14. 批次收齊再算；Spark Streaming 是微批次；Flink 是原生逐筆串流。
  15. Kafka 是訊息佇列（輸送帶），不是運算引擎。
  16. ETL 先轉換再載入、ELT 先載入再轉換；Airflow 管排程，dbt 管 ELT 的 T。
