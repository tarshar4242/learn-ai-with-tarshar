# Tarshar 論文智能島客製造島提示詞

這是準備開工的提示詞，尚未執行或部署。Artifact 可用無敏感內容的示意資料；執行服務入口沿用既有私人網路；論文文件依 10/23 本人決定公開並四處同步。參考視覺來自本人提供的 AgentArk 政策島截圖與提示詞，沒有使用其原始碼。

---

你是創意 Three.js 前端工程師與研究工具設計師。請建立「Tarshar 論文智能島」，讓一位主要用 iPhone 的研究生，看見現在進度、找到正確資料、知道下一步。保留溫暖黏土玩具風、粉彩成片色塊及微縮模型感。先做下面階段一，每階段都交可執行版本與已驗／未驗清單，再接續，不一次塞完整大城。

## 目的與資料邊界

- 原型先在私人服務開發；論文知識庫、工作稿與成果已授權公開，Drive／RAY／GitHub／網站同步。研究寫作正本在 tarshar-vault 的論文線紫區；程式正本在 thesis-semantic-platform。不要複製一套論文正本。
- 現有研究固定兩組：A 嚴格連續字串查找，B 口語理解、檢索、前文、回答及引用。不可因視覺設計變更組別、模型、語料或評分。
- 現有 B 是法規查詢實驗，不是搜尋本人論文草稿；按鈕叫「進入 A/B 實驗」。未建論文資料問答前不要做假的問論文輸入框。
- 有狀態必有來源、日期與版本。沒有資料就寫「待確認」，不可捏造百分比、引用、任務完成或教授核准。
- 示意動畫與真實事件分開。小人走路不代表 AI 正在執行。真實事件要有 run ID、時間、來源與成功／失敗狀態。
- 不顯示模型私密思考鏈；只呈現可觀測步驟與可交付結果。
- 論文工作稿與成果依最新決定公開；前端以選定欄位和正本連結呈現，不公開個資、金鑰或 .env，原始問答先整理刪敏。主機不開 Funnel。

## 五島與造型

1. 研究羅盤：燈塔與羅盤；研究問題、當前方向、待決事項。
2. 文獻書屋：書屋、書堆與閱讀桌；選用文獻、用途、來源與閱讀狀態。
3. 實驗島：並排的 A／B 小實驗室、一座方法亭、一張人工核對桌；A/B 入口、方法、開發驗證與待完成正式評分。
4. 章節書房：五個章節書格與書桌；目前聚焦第三章，未完成章節明標。
5. 會議碼頭：小碼頭與討論桌；教授意見、待討論、交班、下一步。

綠區為歷史港口入口，不列為現行完成成果。五島 axial 座標建議 (0,0)、(1,0)、(-1,0)、(0,1)、(-1,1)，可依手機構圖調整但保持相連。

## DATA 契約

所有文字、連結、狀態、建物、協作關係寫在 DATA，畫面與清單讀同一份。頂層 schemaVersion、generatedAt、sourceCommits、visibility、islands、flows、events。

island: id, title, subtitle, axial, color, items。
item: id, title, description, status, sourceUrl, sourceRevision, updatedAt, verifiedBy, nextAction, model。
model 只指 3D 造型種類；語言模型欄位另叫 runtimeModel。
flow: id, from, to, relationType（dependency／handoff／illustration）, sourceUrl, eventId。
event: id, runId, timestamp, stage, status, sourceRef, sanitizedSummary；未接事件時空陣列。

狀態區分未開始、進行中、待本人核對、待教授確認、已驗證、歷史。文獻選入不等於已讀；AI 摘要不等於本人理解。快照超過 24 小時提示非即時，不憑快照啟動任何任務。

沒有獲得真實快照時，用明標示意資料建立原型，來源留空並顯示待補，不猜造網址。資料先白名單抽取、再掃描去敏，才交前端。

## 視覺與技術

- 原型單一 HTML、原生 ES Modules、不用 React 或建置工具。Three.js 固定 0.160.0；原型 importmap 指向 jsDelivr 相同版本。只使用 OrbitControls、CSS2DRenderer、RoundedBoxGeometry、BufferGeometryUtils、SimplexNoise 中實際必要的部分。私人正式版將相同版本依賴存入服務，離線可載入；這版可拆資料檔，不把單檔限制當長期架構。
- 不載入外部圖片、模型或字型；幾何程式生成、貼圖 canvas。字型系統 PingFang TC／Microsoft JhengHei／sans-serif。
- mulberry32 固定種子，噪聲同源；每次景物相同。
- 六角島 R=2.02、SPACING=2.28、TOP=.65、WATER_Y=-.18；x=√3×SPACING×(q+r/2)，z=1.5×SPACING×r。小橋連步道，避免建物重疊。
- 相機 fov32，OrbitControls 阻尼、禁止平移，初始全景依五島 bounding box 與裝置比例計算，不沿用十二島的固定距離。
- 柔和暖光、霧面黏土、奶油／珊瑚／鼠尾草綠／淡紫色塊、淺海水。只讓太陽投影；手機 pixelRatio ≤1.4。
- 靜態零件共用幾何及 InstancedMesh；首版每島少量建物、少量樹，不做數千背景樹。
- 預設白天。提供清晨、白天、黃昏、夜晚，日夜動畫可關。prefers-reduced-motion 開啟時凍結所有自動動畫與相機飛行，即時監聽偏好變更。
- HTML 先產生可讀清單，再在 try/catch 中 await import() 初始化 3D；載入、WebGL 失敗或 context lost 時維持清單與錯誤訊息，不白畫面。localStorage 讀寫各自 try/catch。
- ResizeObserver、頁面隱藏暫停、無動畫及互動不持續渲染；dt 上限 .08。

## 手機與操作

- 首屏：一張「目前進度／下一步／更新時間」卡、五島地圖、島嶼／清單切換。
- 點島開 bottom sheet（桌面用側卡），優先只列狀態、依據、下一步、開啟正本。44px 觸控區、16px 正文、鍵盤可操作、Escape 關卡片。
- 清單模式提供全部同等內容與連結，不必成功拖曳 3D 才能使用。
- 拖曳不觸發點擊；pointerup 移動 ≤6px 才選取。相機飛行可由使用者中斷。
- 任務執行按鈕在後端尚未串接時不顯示為可用，不做只彈成功提示的假功能。
- 私人網路入口需 Tailscale。若連線失敗提供具體說明；整站不可達時的操作說明放在另可取得的文件。

## 五階段交付

1. 五島骨架：水、光、相機、橋、島名與清單回退；先完整可跑。
2. DATA 與入口：真實快照或明標示意、卡片、來源、下一步、既有平台／架構圖入口。
3. 小景物：書、桌、燈、樹與五島造型，日夜選擇及手機效能收斂。
4. 流程：先標示意重播；另經唯讀 adapter 接實際事件後才顯示真實狀態。日誌不可由隨機小人抵達自動假造。
5. 驗收：桌面與 390×844、iPhone 真機、清單、鍵盤、減少動態、CDN／WebGL 失敗、錯誤連結、狀態與來源、無敏感資料；效能實測列裝置與指標。

每階段提交：可執行檔、如何開啟、資料來源、完成／未完成、驗證結果與下一步。沒有跑過的檢查直說未測，不宣稱到達 30 FPS。第一版的兩個核心驗收動作為：章節書房開啟紫區第三章正本；實驗島進入原有 A/B 平台。
