# 行程管理 PWA — 設定頁逆向工程規格書

> 本文件以逆向工程（前端原始碼還原）方式，重建一款行程管理 PWA「設定頁」及其相依系統的完整規格。目標是**行為完全一致、可據以重寫**。
> 已依要求**移除所有人名、聯絡信箱、對外網域、OAuth 憑證與產品品牌名**；第三方服務一律改用「功能角色」描述（例：某雲端 AI 視覺辨識服務、某 OAuth 行事曆服務、某企業郵件行事曆、某即時通訊軟體）。

## 0. 系統概觀

| 項目 | 內容 |
| --- | --- |
| 產品型態 | PWA（漸進式網頁應用），手機優先、可安裝到桌面 |
| 核心價值 | 拍照辨識會議通知單 → 建立行程 → 本機管理 → 匯出／同步到外部行事曆 |
| 前端框架 | Next.js（App Router，客戶端渲染，含 Store Provider 全域狀態） |
| 語系 | 繁體中文（`lang="zh-Hant"`） |
| 資料儲存 | **全部本機**：行程主資料庫用 IndexedDB；偏好設定與本機備份用 localStorage；OAuth token 用 sessionStorage。**不上傳雲端**（拍照辨識除外，見 §2） |
| 時區基準 | Asia/Taipei（配額重置、日曆 OAuth 皆以台灣時間為準） |
| 視窗設定 | `viewport` 鎖定 `maximum-scale=1, user-scalable=no`；主題色 `#0F4C81` |

**設定頁定位**：使用者集中管理「辨識金鑰／外觀／提醒／行事曆匯出／跨裝置同步」的頁面。頁面掛載前顯示「載入中…」骨架，資料就緒後由全域 Store 提供 `events`（行程陣列）與 `prefs`（偏好設定）。

## 1. 設定頁區塊總覽（由上而下的實際排列順序）

設定頁外層為垂直排列容器（區塊間距一致、左右留白）。頁首標題為「**設定**」。其下依序為：

1. **辨識金鑰卡**（§2）— 使用者自帶 AI 視覺辨識金鑰
2. **辨識次數說明卡**（§3）— 配額規則與今日用量
3. **外觀與風格**（§4）— 佈景主題選擇
4. **字體大小**（§5）— 小／中／大
5. **預設提醒 + 行程提醒模式**（§6）— 新行程預設提前分鐘數、通知總開關
6. **匯出行事曆**（§7）— 主要行事曆偏好與對應說明
7. **OAuth 行事曆自動匯入卡**（§8）— 僅當主要行事曆選為「OAuth 行事曆」時顯示
8. **匯出行程／分享按鈕 + 對應彈窗**（§9）— 有行程時顯示，無行程時顯示空狀態提示
9. **裝置同步（A → B）**（§10）— 本機備份庫與備份檔跨裝置合併
10. **分享與匯入說明**（§11）— 依 iOS／Android 平台差異呈現
11. **本機儲存說明**（§12）— 一句話聲明資料留在本機
12. **開發者資訊**（§13）— 去識別化後保留欄位骨架
13. **頁尾**（§14）— 隱私權政策／服務條款連結

## 2. 辨識金鑰卡（自帶 AI 視覺辨識金鑰）

**用途**：讓使用者填入自己的「雲端 AI 視覺辨識服務」API Key，用於拍照辨識會議通知單。填入後辨識**不限次數**（改由使用者自己的金鑰計費）。

### 2.1 顯示內容
- 標題：「AI 辨識金鑰（拍照辨識）」，前綴一個金鑰圖示。
- 說明文字（原意保留、品牌去識別化）：
  > 使用您自己的 AI 服務 API Key 進行會議通知單辨識，可**不限次數**。金鑰僅暫存在本次瀏覽階段（分頁全部關閉即自動清除，不會長期留在裝置上），拍照時才透過加密連線傳給伺服器代為呼叫。若未填入，可使用平台每日 10 次免費辨識（伺服器備有兩組 Key 自動切換）；測試階段建議先直接拍照體驗，需要大量辨識再填入自己的 Key。
- 狀態徽章（依是否已填金鑰切換）：
  - 已填（trim 後非空）：綠底「已設定（拍照辨識不限次數）」
  - 未填：琥珀底「未設定（使用平台配額，每日 10 次）」

### 2.2 輸入與操作
- 標籤「API Key」，下方輸入框：
  - 型別在 `password` / `text` 間切換（右側眼睛鈕控制顯示／隱藏，`aria-label` 隨狀態變「顯示金鑰／隱藏金鑰」）。
  - `autoComplete="off"`、`spellCheck=false`、等寬字型。
  - placeholder 提示金鑰前綴格式（例：`貼上 AIza... 開頭的金鑰`）。
- 下方一條外部連結：「前往 AI 服務商申請免費 API Key」（`target="_blank"`、`rel="noopener noreferrer"`，附外連圖示）。
- 底部按鈕列：
  - 主按鈕「儲存金鑰」：呼叫 `updatePrefs({ geminiApiKey: 值.trim() })`，成功後文字暫變「已儲存」2 秒後還原。
  - 次按鈕「清除金鑰」（僅在已有金鑰或輸入框有值時出現）：清空輸入並 `updatePrefs({ geminiApiKey: "" })`。

### 2.3 狀態
- 元件掛載時以 `prefs.geminiApiKey` 初始化輸入值，並在該值變動時同步。
- 判定「已設定」的依據：`prefs.geminiApiKey?.trim()` 非空。

## 3. 辨識次數說明卡

**用途**：純說明性卡片，解釋 OCR（拍照辨識）配額規則，並顯示今日剩餘量。

### 3.1 規則條列
- **未填入 API Key**：使用平台辨識服務（雙 Key 自動備援），每日限 **10 次**（以台灣時間每日 0:00 重置）。
- **已填入自己的 API Key**：改由使用者金鑰計費，**不限次數**。
- 手動輸入行程**不計入**辨識次數。
- 僅在拍照成功完成 AI 辨識（非示範資料）時才**扣 1 次**。

### 3.2 今日用量提示
- 若非不限次數，顯示：「您今日已使用 {used} / {limit} 次，剩餘 {remaining} 次。」
- 用量計算邏輯（見 §15.4 配額函式）。

## 6. 預設提醒 + 行程提醒模式

### 6.1 預設提醒（新行程預設提前分鐘）
- 下拉選單，選項固定為 **5 / 15 / 30 / 60** 分鐘，文案「新行程預設 {n} 分鐘前提醒」。
- 寫入 `prefs.defaultReminderMinutes`。
- **僅在通知模式為「已允許」時可用**，否則下拉呈半透明停用。

### 6.2 行程提醒模式（通知總開關）
三選一卡片，寫入 `prefs.notificationMode`：

| value | 標籤 | 說明（卡片小字） | 徽章 |
| --- | --- | --- | --- |
| `allowed` | 已允許 | 會議前跳出提醒通知 | success |
| `blocked` | 已封鎖 | 不接收任何行程提醒 | error |
| `unset` | 尚未設定 | 暫不啟用提醒功能 | warning |

- 目前模式對應一段動態說明文字：
  - allowed：「已開啟提醒。選擇後若瀏覽器詢問，請點『允許』以接收系統通知；App 開啟時也會顯示畫面提醒。」
  - blocked：「已關閉提醒，不會收到任何通知。可隨時在此改回『已允許』。」
  - unset：「尚未啟用提醒。選擇『已允許』即可開始使用，無需到其他設定頁。」
- 切換模式時（若與目前不同且未在忙碌中）：先 `updatePrefs({ notificationMode })`，再依新模式重排所有行程的通知排程（見 §15.3）。切換期間三顆卡片停用。

## 8. OAuth 行事曆自動匯入卡

> **顯示條件**：僅當 `prefs.primaryCalendar === "google"` 時渲染此卡。

分兩種狀態：

### 8.1 已設定 OAuth Client ID（功能可用）
- 標題「OAuth 行事曆自動匯入」＋行事曆圖示。
- 說明：「連結帳號後，儲存或匯出時可**一鍵自動新增**到您的行事曆（含多場批次），無需下載 `.ics`。」
- 狀態徽章：綠底「已連結帳號」／琥珀底「尚未連結」。
- 按鈕：
  - 未連結 → 「連結帳號」（連結中顯示「連結中…」並停用）。成功後顯示「已連結帳號，匯出時將自動寫入日曆」。
  - 已連結 → 「解除連結」。解除後顯示「已解除帳號連結」。
- 底部灰字提示：「若僅部分帳號能連結，代表 OAuth 仍在測試模式，需由管理員加為測試使用者或發布正式版。」

### 8.2 未設定 OAuth Client ID（功能不可用）
- 虛線邊框卡，標題同上但圖示轉灰。
- 說明：管理員尚未設定 OAuth Client ID 環境變數（`NEXT_PUBLIC_GOOGLE_OAUTH_CLIENT_ID`），目前僅能手動開啟網頁或下載 `.ics` 匯入。

### 8.3 OAuth token 機制（見 §15.5）
- token 存 sessionStorage，含 `accessToken` 與 `expiresAt`。
- 視為有效的條件：`expiresAt > 現在 + 60 秒`。
- 是否具備連結能力：環境變數 OAuth Client ID 長度 > 0。

## 9. 匯出行程 / 分享（有行程時）

- **當 `events.length > 0`**：
  - 主按鈕「匯出行程」→ 開啟匯出彈窗（傳入全部行程、主要行事曆偏好、以本月為優先月）。
  - 次按鈕「分享」→ 開啟分享彈窗。
  - 兩個彈窗元件受 `open` 狀態控制開關。
- **當無行程**：顯示虛線框空狀態：「尚無行程可匯出，請先新增會議」。

### 9.1 `.ics` 產生規格（iCalendar）
匯出的行事曆檔為標準 VCALENDAR / VEVENT：
- 每筆 VEVENT 欄位：`UID:{id}@<app-id>`、`DTSTAMP`、`DTSTART`、`DTEND`（皆為本地時間格式 `YYYYMMDDTHHMMSS`）、`SUMMARY`（標題）。
- 選填：有地點加 `LOCATION`、有備註加 `DESCRIPTION`。
- 提醒：`reminderMinutes > 0` 時加 `VALARM`（`ACTION:DISPLAY`、`TRIGGER:-PT{n}M`、`DESCRIPTION:行程提醒`）。
- 文字需 iCal 逸脫（`\` `,` `;` `\n`），並依 75 字元折行（續行前置空白）。

## 10. 裝置同步（A → B）

**設計原則**：資料不上雲。A 裝置匯出 → B 裝置匯入本機資料庫（IndexedDB）完成合併。

### 10.1 A 裝置：匯出（三顆按鈕）
1. **儲存到本機備份庫（{n} 場）**：把目前行程序列化存入 localStorage 備份鍵。成功後顯示已存筆數、備份時間（`yyyy/M/d HH:mm`），並提示可在本機或他機「從本機備份庫匯入」；跨裝置仍需先下載／分享備份檔。
2. **下載備份檔（跨裝置傳輸）**：下載 `.json` 備份，提示可傳到 B 裝置後匯入。
3. **分享備份檔（即時通訊／Email）**：優先用 Web Share API 附檔分享；不支援時退回下載。回傳 `shared`／`downloaded`／`cancelled`／`empty` 對應不同提示。
- 三顆按鈕在忙碌中或無行程時停用。

### 10.2 B 裝置：匯入到本機資料庫（兩種來源）
1. **從本機備份庫匯入到資料庫**：讀 localStorage 備份鍵，驗證後計算合併差異。無備份庫資料時停用，並顯示「本機備份庫尚無資料；跨裝置請先從 A 傳備份檔到此裝置」；有資料時顯示筆數與備份時間（`M/d HH:mm`）。
2. **選擇備份檔匯入到本機資料庫**：隱藏的檔案輸入（`accept=".json,application/json"`）。選檔後：
   - 檔案大小超過上限（**10 MB**）→ 報「檔案過大（上限 10MB）…」並清空輸入。
   - 讀文字 → 解析驗證 → 寫回本機備份庫 → 計算合併差異。
   - 解析失敗 → 「讀取檔案失敗，請確認檔案完整」。

### 10.3 匯入確認面板
計算出差異後彈出確認框：
- 顯示備份時間（`yyyy/M/d HH:mm`）。
- 條列：新增 {toAdd} 場、更新 {toUpdate} 場、（若有）略過 {skipped} 場（本機較新）、（若有）略過 {invalid} 筆格式錯誤。
- 底部聲明：「僅合併備份中的行程，不會刪除本機獨有的行程。」
- 「確認匯入資料庫」（匯入中顯示「匯入中…」）／「取消」。
- 若差異為 0（無新增無更新）：直接提示「本機資料已是最新，無需匯入」（附略過格式錯誤數，如有）。

### 10.4 備份檔格式與驗證（見 §15.6）
- 格式：`{ version:1, app:"<app-id>", exportedAt:ISO, events:[...] }`，events 依 `startAt` 升冪排序。
- 檔名：`<app-id>-sync-YYYYMMDD.json`。
- 驗證失敗訊息（逐項）：非 JSON、非物件、app 不符、版本不符、缺 events 陣列、筆數過多（上限 **5000**）、全部無法辨識。
- 合併規則：以 `id` 對應本機行程；
  - 本機無此 id → 新增（toAdd）。
  - 匯入的 `updatedAt` 較新 → 更新（toUpdate）。
  - `updatedAt` 相同 → 逐欄比對（title/startAt/endAt/location/notes/color/reminderMinutes），完全相同則略過（skipped），否則更新。
  - 匯入較舊 → 略過（skipped）。

## 11. 分享與匯入說明（依平台）

標題依平台顯示「分享與匯入說明（Android）」或「（iPhone）」。三段共通說明 + 一段平台專屬提示：

1. **分享連結給同事**：行程詳細頁 → 分享 → 複製分享連結 → 貼到即時通訊軟體；對方點連結，App 自動帶入行程，一鍵儲存（不耗 AI 配額）。
2. **分享文字＋.ics 附檔**：
   - Android：分享到即時通訊／社群，通常可同時附文字與 `.ics`；對方可用本 App 開啟或加入手機日曆。

## 15. 相依資料模型與跨頁系統（設定頁行為所依賴）

### 15.1 偏好設定 `prefs`（預設值）

```
fontScale: "md"

```

### 15.2 行程 `Event` 資料結構（由備份驗證器還原）
| 欄位 | 型別／限制 |
| --- | --- |
| `id` | 非空字串，≤ 200 字元 |
| `title` | 非空字串，trim 後截斷至 ≤ 200 字元 |
| `startAt` / `endAt` | 可被 `Date` 解析的字串，長度 ≤ 64 |
| `location` | 字串，≤ 200 字元（預設空字串） |
| `notes` | 字串，≤ 4000 字元（預設空字串） |
| `color` | 由來源／優先度推導（見 §15.7） |
| `source` | `ocr` / `manual` / `booking`（不在此集合則歸為 `manual`） |
| `reminderMinutes` | 數字 ≥ 0，上限 10080（7 天）；預設 0 |
| `createdAt` / `updatedAt` | ISO 字串，缺漏時以當下時間補 |

### 15.3 通知排程系統
- `notificationMode === "allowed"` 時，為每筆行程排一個 `setTimeout`：
  - 觸發時間 = `startAt − reminderMinutes×60秒 − 現在`。
  - **僅當該值介於 0～604800000 毫秒（7 天內）才排程**；過期或超過 7 天不排。
  - 觸發時：若 `Notification.permission === "granted"` → 發系統通知（標題「即將開始：{title}」，內文為「時間 · 地點」）；否則若文件可見 → 派發 `schedule-reminder` CustomEvent 供 App 內畫面提醒。
- 切換到 `allowed` 會先請求通知權限再重排；切到其他模式會清空所有排程。
- 全域 Store 初始化載入行程後，即依當前 `notificationMode` 排程一次。

### 15.4 OCR 配額計算
- 「今天」以 `Asia/Taipei` 時區、`en-CA`（`YYYY-MM-DD`）格式判定。
- 若已填自帶金鑰 → `{ unlimited:true, used:0, limit:0, remaining:0, usesSharedQuota:false }`。
- 否則：`used = (ocrQuotaDate === 今天 ? ocrQuotaUsed : 0)`，`limit = 10`，`remaining = max(0, 10 − used)`。
- 是否可再辨識：不限次數或剩餘 > 0。
- 扣次數：回傳 `{ ocrQuotaDate: 今天, ocrQuotaUsed: (同日則+1，否則從1計) }`。

### 15.5 OAuth 行事曆連結
- token 存 sessionStorage（鍵：`<app-id>-google-calendar-token`），結構 `{ accessToken, expiresAt }`。
- 有效判定：`expiresAt > 現在 + 60000ms`。
- 具連結能力：環境變數 OAuth Client ID 長度 > 0。
- 解除連結：若 token 存在且 OAuth SDK 就緒則呼叫 revoke，最後移除 sessionStorage。
- 時區固定 `Asia/Taipei`。

### 15.6 備份格式常數
| 常數 | 值 |
| --- | --- |
| IndexedDB 資料庫名 | `<app-id>` |
| 本機備份 localStorage 鍵 | `<app-id>-local-backup` |
| 備份檔大小上限 | 10 MB（`0xa00000` = 10485760 bytes） |
| 標題／地點截斷 | 200 字元 |
| 備註截斷 | 4000 字元 |
| 單一備份筆數上限 | 5000 |
| 備份版本 | `1` |

### 15.7 優先度／顏色對應
| 優先度 key | 標籤 | 色碼 | 說明 |
| --- | --- | --- | --- |
| `high` | 最重要 | `#DC2626` | 必須參加、主管會議等 |
| `medium` | 中等 | `#EAB308` | 重要但可協調 |
| `low` | 普通 | `#16A34A` | 一般行程 |

來源／別名 → 優先度對應：`meeting→high`、`travel→medium`、`personal→low`、`other→low`、`high/medium/low` 維持原值；無法辨識時預設 `medium`。

## 16. 全域狀態（Store）契約

設定頁透過全域 Store 取得與更新資料，介面：
- 讀取：`events`（行程陣列）、`prefs`（偏好）、`ready`（是否載入完成）。
- 方法：`refresh()`、`upsertEvent(e)`、`mergeImportedEvents(list)`、`removeEvent(id)`、`updatePrefs(patch)`。
- 初始化：並行載入行程與偏好 → 設定狀態 → 依 `notificationMode` 排程通知 → 標記就緒。
- 任何 `upsert` / `merge` / `remove` 後都會重新 `refresh`（重載並重排通知）。
- `updatePrefs` 回傳更新後的完整 prefs 並就地更新狀態。
