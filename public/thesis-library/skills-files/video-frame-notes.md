# 影片逐幀筆記

## 這個 skill 解決什麼

課程影片沒辦法搜尋、沒辦法快速回顧、看過就忘。這個 skill 把一整個資料夾的影片變成：

- **`index.html`** — 封面牆，雙擊就能看，點卡片進單支筆記
- 每支影片一個資料夾，裡面三個檔：
  - `筆記.html` 圖文對照（關鍵畫面＋字卡文字＋那段講了什麼）
  - `筆記.md` 同樣內容，可丟 Obsidian 或知識庫
  - `逐字稿.txt` 純文字全文含時間戳，要搜整句話時用

## 怎麼跑

```bash
python3 <skill>/scripts/make_notes.py "<影片資料夾>"
```

常用選項：

- `--only 01,03` 只處理特定幾支（先拿一支試跑，確認效果再跑全部）
- `--out <資料夾>` 換輸出位置（預設 `<影片資料夾>/逐幀筆記`）
- `--prompt "..."` **強烈建議填**。把課程的專有名詞寫進去，可以大幅減少工具名被聽錯
- `--author 知臨` 署名

四個階段（逐支落檔，中斷後重跑會跳過已完成的）：① 逐字稿 → ② 關鍵畫面 → ③ 合成 → ④ 自檢。

跑完**一定要自己開 `index.html` 看一眼**，自檢只驗檔案和連結，不驗好不好看。

## 環境需求

| 需要什麼 | 怎麼裝 | 沒有會怎樣 |
|---|---|---|
| ffmpeg / ffprobe | `brew install ffmpeg` | 完全不能跑 |
| mlx-whisper | `pip3 install --user mlx-whisper` | 沒有逐字稿 |
| opencc | `pip3 install --user opencc-python-reimplemented` | 腳本直接停 |
| Pillow | `pip3 install --user Pillow` | 完全不能跑 |
| Xcode CLT（swiftc） | `xcode-select --install` | 字卡文字會留白，其餘正常 |

速度參考：Apple M4 上約 **17 倍速**（127 分鐘影片，逐字稿約 8 分鐘、畫面約 3 分鐘）。

**不要用 `transcribe` skill 做這件事**——那個要 `OPENAI_API_KEY`（Tarshar 沒設），而且要把影片音訊上傳。本 skill 全程本機、免費、離線。

## 為什麼是這些數字（踩過才知道的）

改參數前先看這段，這些不是隨便設的。

### 一、抓幀要「切換點之後 1.2 秒」，不能抓切換點本身

場景偵測回報的是**轉場正在發生**的那一刻，直接抓會拿到淡入淡出的糊畫面或全黑畫面。第一版 15 張裡有 4 張是黑的。

修法：`OFFSETS = [1.2, 2.2, 0.6]` 往後偏移，並且丟掉「平均亮度 < 22 或標準差 < 12」的畫面（純色轉場），不合格就換下一個偏移再試。

### 二、講者鏡頭和字卡要分開去重，不能用同一個門檻

課程影片是「講者鏡頭 ↔ 字卡」交錯。用單一門檻去重，講者鏡頭穿插在字卡之間會躲過比對，結果一半的圖是同一張人臉。

修法：先用**平坦度**（畫面最大同色塊佔比）分類，`>= 0.38` 是字卡。字卡之間用嚴格門檻 6（不同字卡都要留），講者鏡頭之間用寬鬆門檻 14（長得像就丟），而且和**所有**已保留的比對，不只最近幾張。

### 三、`condition_on_previous_text=False` 會讓逐字稿沒有標點

為了防長影片幻覺而關掉它，副作用是整段黏成一長串沒有斷句，完全沒辦法讀。**保持 True。**

### 三之二、`--prompt` 不能塞長名詞清單，長影片還會「飄掉標點」

2026-08-09 做直播電台 EP48（62 分鐘）踩到的兩件事：

**（a）prompt 要短、要是自然句子。** 塞了 25 個名詞的頓號清單下去，模型從 18 分處開始標點全掉（92% 段落沒標點），還在句子之間吐出莫名其妙的全形「Ｂ」。改成一句話就正常了：

```
以下是關於 Excel 巨集、增益集、VBA 程式碼，以及 Gemini Spark 與 NotebookLM 的中文說明。
```

**（b）長音檔會累積壞習慣，一飄就一路壞到底。** 保持 True 是對的，但單次餵 60 分鐘，前段一旦掉標點後段全毀。修法是**切成 120 秒一段分別辨識**（時間戳自己加回偏移），偵測到某段超過一半沒有標點就切成 60 秒重試。EP48 用這個做法把無標點段落壓到 10%。

可重用的腳本：`100_Todo/projects/課程｜直播電台EP48｜逐幀筆記/分段語音辨識.py`，改開頭的影片路徑就能跑。

### 三之三、全螢幕分享的影片，OCR 畫面索引沒有價值

字卡分類會把整場螢幕分享都判成字卡，OCR 抓到的是網址、工具列、字型名稱（「Arial」「常用」）。這種片子**不要靠自動產生的畫面索引**，要另外讀逐字稿手寫章節目錄。

### 四、whisper 中文會中途飄成簡體，用 s2tw 不要用 s2twp

開頭繁體、後段簡體是常態。用 OpenCC 統一還原，但**只能用 `s2tw`（字形還原）**。

`s2twp` 會連用詞一起換：「優化」→「最佳化」、「數據」→「資料」。那是在改講者的講法，不是修錯。修錯可以，改人家怎麼講不行。

### 五、講者鏡頭的 OCR 不能當標題

會讀到衣服上的字。實際發生過：把 WORK SMART 讀成「JRK SMA」放進畫面索引。分類是 talker 的就不要用 OCR 當標題。

### 六、語音單元要另外處理

有些單元是「語音課程」，畫面全程固定。保留畫面 ≤ 2 張時視為語音單元，改成每 120 秒切一段，不然整份逐字稿會全部塞在同一張圖底下。

## 流程上的教訓（比參數更重要）

**先用 90 秒樣本驗證輸出格式，再跑全部。而且改任何參數之後要重驗。**

實際發生的事：跑了 90 秒樣本、確認品質很好，然後「順手」把 `condition_on_previous_text` 改成 False 就直接跑完 10 支，做完筆記才發現標點全沒了，整批重跑。

樣本測試的意義是驗證**當下這組參數**，不是驗證「這個工具會動」。改了就要重驗。

## 交付前要檢查什麼

腳本的 `④ 自檢` 只驗檔案齊不齊、圖片連結斷不斷。**這些要人工看**：

1. 開 `index.html`，隨機點兩支進去看
2. 畫面索引的標題有沒有亂碼或無意義的字（OCR 讀錯）
3. 口述內容有沒有標點、有沒有簡體字
4. 拿一支影片的某個時間點，對照筆記上的內容對不對得起來

## 已知限制（要跟她講清楚，不要假裝沒有）

- 逐字稿是機器產生的，**人名和工具名會聽錯**。腳本裡的 `FIX` 只修可確定的（ChatGPT、Heptabase、Gemini、Midjourney、OpenAI、Readwise Reader）。不確定的一律保留原樣，不要猜。
- 引用到作業、貼文、簡報之前要對照影片。
- 字卡 OCR 準確度高但不是 100%，小字和特殊字型會漏。

## 選配步驟：把 Notion 文稿整合進來（`scripts/merge_notes.py`）

課程如果同時有影片和 Notion 文稿，這一步把兩份合成「三合一自足頁面」，以後只要看這份就夠。

**什麼時候值得做**：影片有明確的教學結構（KIT 模型：生活觀察→認知誤區→策略應對→行動練習）、文稿保留了章節與超連結、想要「一頁看完」的體驗。

**兩份為什麼互補而不是重複**：文稿是「這集在講什麼概念」（有結構、有連結），逐幀筆記是「老師實際怎麼講、示範了什麼畫面」（有時間軸、有口述）。語音單元的文稿反而會補齊我抓不到的關鍵字卡；操作展示單元的逐幀筆記則補齊了文稿裡沒有的畫面過程。

**流程**（在 make_notes.py 和 dl_notion_public.py 都跑完之後）：

```bash
python3 scripts/merge_notes.py \
    "<影片資料夾>/逐幀筆記" \
    "<影片資料夾>/教材下載/課程文稿" \
    --out "<影片資料夾>/整合筆記" \
    --title "課程系列名稱"
```

**配對規則**：兩邊都用**開頭兩位數字**（01、02、...）當單元編號來對齊。只整合兩邊都有的單元；只有影片沒有文稿、或只有文稿沒有影片的都會被跳過並回報清單——這個報表有用，可以看出還缺哪些對應。

**輸出結構**：每支影片一個 `整合筆記.html`，三個區塊 + 頂端跳轉按鈕：
- 📖 教學文稿（Notion 精華、保留章節與超連結）
- 🎞️ 畫面時間軸（我抓的關鍵畫面＋字卡文字＋該時段口述）
- 📝 完整逐字稿（`<details>` 摺疊，預設收起，要引用時才展開）

**注意**：這步驟不改動原本的逐幀筆記，只是**另建**一份整合版。原本的兩份都還在，需要單看時可以用。

## 附帶工具：`scripts/dl_notion_public.py`

課程常把文稿放在 Notion 公開頁。這支可以整批抓成 Markdown，不用登入、不用 API 金鑰。

```bash
# 先看這頁裡有哪些資料庫
python3 scripts/dl_notion_public.py --out ./文稿 --list <頁面id>
# 抓整個資料庫
python3 scripts/dl_notion_public.py --out ./文稿 --collection <cid> --view <vid>
```

眉角：

- 只對**已公開分享**的頁面有效。私人頁面要走登入的瀏覽器。
- Notion 會限流（429）。腳本每頁隔 3 秒並自動退避，**不要調快**，快了會整批失敗。
- rich text 的超連結藏在格式標註裡，只取文字會把連結全部弄丟——`rt()` 已處理，不要簡化掉。
- **表單頁抓不到內文**（內容是表單元件），要另外用瀏覽器讀。
- 圖片只會留佔位標記，不會下載。要完整版就用 Notion 官方的「複製」鍵複製到自己的工作區。
