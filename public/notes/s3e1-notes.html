3 · 台語 TTS

TTS益值玩與台語生態系 [08:00–36:00]

本堂主角。從「為什麼台語 TTS 難」講到「怎麼跟 Claude 聊出一個多引擎語音實驗室」。

3.1 台語的家底：意傳科技（ithuan.tw）

  • 台灣本土團隊，維護台語、Pangcah（阿美語）、Kaxabu（噶哈巫語）、客話等語言專案，出品「厝鳥仔講台語」App。
  • 提供「標漢字音標」（分詞＋台羅標音）與「台灣媠聲」（語音合成）API——是 TTS益值玩台語聲音的來源。
  • 限制：每 IP 每分鐘最多 3 句音檔——連按太快就沒聲音，工具內建「逐句合成＋節流」來配合。
  • 加映：Node-RED 也接得起來——「台語語音節點案例」流程：inject 繁中→「繁中轉台語語音」節點（ithuan）→台語漢字輸出／存 MP3／Buffer／編輯器播放。除錯窗誠實標註「台語漢字為規則式草稿，正式用途請人工確認」。[15:20]

3.2 TTS益值玩 (9)：多引擎台語語音實驗室

功能內容
語言14 種：台語（預設）、華語（原文直接發音，不經翻譯）、英日韓西法德義葡越泰印尼粵
四引擎台灣媠聲（台語，免 API 金鑰）／ElevenLabs（填 Voice ID＋Key）／Gemini TTS／瀏覽器 TTS（免費，但無法輸出 MP3）
台語輸出台語漢字（教育部推薦用字）＋台羅拼音（可手動編修重新合成）＋用詞解說
批次合成多句一次跑→ZIP（逐句 mp3＋combined.mp3＋SRT 字幕＋index.csv）；HTS 引擎每 3 句自動斷流配合意傳限制
字幕影片單句或批次結果皆可→Canvas 渲染動態字幕影片，優先輸出 MP4——開場那支颱風新聞影片就是這裡出來的
核心流程圖：一句繁中到一顆台語 MP3 要過四站，每一站都有 7/9 對話裡真實踩過的坑與對策。

3.3 這個工具是怎麼「聊」出來的：7/9 vibe-coding 對話全重播 [18:40–22:00]

  1. 起手需求：「針對 YouTube 台語運用影片做獨立網頁，輸入繁中→轉台語→mp3 下載，資料整理透過 Groq API。」
  2. 管線設計：繁中→Groq 轉台語漢字＋台羅＋解說→意傳「標漢字音標」分詞標音→台灣媠聲合成→lamejs 前端轉 MP3（附 WAV 備援）。
  3. 抗 429 降級鏈：gpt-oss-120b→llama-3.3-70b→llama-4-scout→maverick→llama-3.1-8b，額度滿了自動換下一棒。
  4. 強韌解析：Groq JSON mode 失敗自動退一般模式；三段式解析（直接 parse→撈最外層 {} 修補換行→逐欄位 regex），自動剝 <think> 與程式碼圍欄；解析器 6/6 測試通過＋Playwright 端對端驗證。
  5. 除錯實錄：音檔空白＝送錯格式伺服器回錯誤頁→加 magic bytes（fffb）與 Content-Type 驗證；發音不道地（「食飯」唸錯）→查官方作法改逐句分開合成＋台羅欄位開放手動編修。
  6. 道地性 prompt：加嚴格對應表＋鐵則「寧可改寫句構、不可保留華語詞」（咱一起去→咱做伙去）；意傳標音不可用而退回 Groq 推估時，畫面明確標「台羅為 AI 推估」。
  7. 大改版：台語降為 14 種語言之一→「選語言 × 選引擎」通用 TTS 平台；課前又加碼串 ElevenLabs（Voice ID）、Gemini TTS、瀏覽器 TTS。
🧭 為什麼要重播對話？因為工具本身會過時，但「需求怎麼講、卡關怎麼問、AI 的錯怎麼抓」這套過程才是可複製的。學員羅州課後回饋：自己也試過台語 TTS，「意傳好很多」。

5 · 風格復刻

圖像風格復刻三件套 [38:40–65:20]

「風格」不再是感覺，是一份可以量化、可以重複使用的規格書。

6 · 反向工程

HTML 反向工程 R2：程式拆回提示詞，再讓三家 AI 重建 [96:40–106:00]

下半場開場即核心觀念：提示詞才是資產。程式碼 99,667 tokens，拆回提示詞只要 1,629 字。

  • 設定面：Groq Key 可多組（每行一把自動輪換）、模型 llama-3.3-70b、創意溫度 0.35、TPM 上限 6000（免費層 8b=6000/70b=12000）、自動壓縮以符合 TPM、附帶 One-Shot 範例（TPM 不足自動改精簡）。
  • 四種模式：單檔反向／差異比對（v1→v2 改了什麼）／圖像反向／批次 ZIP。另可匯出 .puml（PlantUML 流程圖）。
  • 提示詞九章：⋯4 版型結構（Header/Content/Footer）、5 元件清單與規格、6 功能規格（核心流程＋錯誤容錯）、7 實作陷阱（Canvas/DPR、座標換算、API 回傳尺寸、SSE 串流解析、CORS、localStorage）、8 文案與語氣、9 一句話濃縮版。
反向工程的價值鏈：程式碼壓成 1.6% 大小的提示詞，再讓任何模型重建回可用的工具。

重建驗證：同一份提示詞，三家各蓋一棟

  • Gemini Canvas：重建版含台語翻譯＋Gemini TTS（Aoede）＋預留 ElevenLabs 欄位＋Canvas 字幕影片模擬。
  • LMArena（Max 模型）：「I'll create this TTS Playground…」→產出 taiwanese-voice-lab：四引擎籤（台灣媠聲 FREE／ElevenLabs／Groq Orpheus／Gemini TTS）＋操作記錄。
  • claude.ai（Fable 5）：附上提示詞後 Claude 反問四選項——直接生成／先強化再生成／只強化提示詞／評估缺漏——示範「提示詞本身也能再進廠保養」。
🎯 這一段在教什麼：①別人的好網頁→圖像反向→提示詞；②自己的舊程式→單檔反向→提示詞庫；③大改版前先跑差異比對。提示詞在手，換哪家模型都能把工具重建回來——這就是「不被平台綁架」的保險。
7 · 資料工具

資料雙工具：數據清洗 v6 × 意境壓縮器 v2 [106:40–124:40]

7.1 數據清洗、正規化及分析 v6：Excel 老手的 AI 分析台

  • 吃得下的格式：CSV／TSV／JSON／Excel（多工作表自動拆）／SQLite（.db）／SQL 傾印（含 MySQL dump）／Access（.mdb/.accdb），可多檔多資料集。
  • 七個分頁＝一條分析流水線：資料載入→數據檢視→數據清洗→正規化→分析圖表→資料關聯→進階分析建議。
  • AI 清洗建議：依欄位剖析列「清洗優先清單」（每項含問題／建議做法／風險等級）＋自動可修復項。
  • AI 正規化策略：數值欄位處理、類別欄位編碼（Label／One-Hot）、1NF/2NF/3NF 拆表建議、五步前處理流水線。
  • 互動圖表：不知道選哪種？點「建議圖表」一鍵產生（占比→圓餅、排行→長條、分佈→直方）；實測餐廳資料「各名稱Σ銷售量排行」＋Pearson 相關矩陣＋自動洞察（強相關：點選率↔銷售量）。
  • 進階分析建議：①關聯解讀（該怎麼 JOIN）②現在就能做的四種分析（各附演算法＋需要欄位＋能回答的商業問題）③建議補充的資料④後續步驟。

7.2 意境壓縮器 v2 · Token 瘦身引擎：省 70% 的長文預處理

  • 理念來自 microsoft/MarkItDown（GitHub 165k 星）：「用最精簡的標記保留結構，主流 LLM 原生看得懂」——把同樣思路推進到內容層。[122:40]
  • 三檔壓縮強度：L1 結構化（MarkItDown 式 Markdown，保留全部資訊與語氣）／L2 精煉（刪贅字、合併重複、長句改短）／L3 電報體（符號縮寫極限壓縮，仍可還原意境）。
  • 必留項目直接寫進壓縮指令：數字金額日期／專有名詞人名／語氣風格。
  • 數字／專名稽核：自動抓原文的數字與英數專名逐一比對壓縮版，缺了直接亮紅籤（實測遺漏 9/33）＋「AI 補抓」一鍵補。
  • 來源全吃：貼上／PDF/TXT/MD／網頁 URL（Jina Reader 抓文）／圖片 OCR（Llama-4 Vision）／音檔（Whisper v3 turbo 轉錄再壓縮，上限 25MB）；內建 TPM 節流、TPD 降級、429 重試、多金鑰輪替。

8 · SWOT

AI SWOT 分析工具：貼個網址就能打商戰 [126:40–169:20]

9 · 技能化

壓軸：把 HTML 工具變成 Codex 全域 Skill [133:20–141:20]

整堂課的收束點：工具的下一站不是更多按鈕，而是「一句話」。

講師的完整 prompt（一字不改）： 請將上傳的程式 改為 PDF拆分工具.skill 可以根據提供的PDF檔 幫我做章節的切割並提供切割後的每個PDF檔給我， 切割後的PDF需要列外製作一個資料夾，這個skill 為全域
  1. 先查重：Codex 發現本機已有 ebook-chapter-splitter skill→「精準更新，不重複製造兩個功能相同的 skill」→決定另建觸發更直覺的 pdf-split-tool。
  2. 關鍵取捨：「HTML 前端本身不能在 Codex skill 裡穩定批次產出 PDF 檔」→把核心能力改寫成 Python 腳本，保留自動偵測章節／手動章節範圍／另建資料夾／產出 manifest。
  3. 踩坑實錄：short_description 要 25–64 字元（中文描述太短被驗證器打回）；Windows cp950 讀 UTF-8 中文解碼失敗→改 UTF-8 重跑；中文路徑干擾→改放系統暫存目錄。
  4. 輸出後驗證：切完逐一讀回 PDF 驗證頁數，「避免只『看起來有產生』」。
  5. 成果三檔：skills/pdf-split-tool/SKILL.md（+100）、agents/openai.yaml（+7）、scripts/split_pdf_chapters.py（+361）→重啟 Codex→輸入 /pdf 出現「PDF Split Tool」；用法：「使用 $pdf-split-tool，幫我把這份 PDF 依章節切割」。
  6. 開源收尾：整個 skill 推上 GitHub（yangchunyi0814/Split_PDF_Chapters），README 列五種切割模式（自動偵測／書籤／目錄頁／頁首標題／manual 人工章節表 chapters.json/CSV——書籤壞掉的 PDF 就靠它）。[180:00]
