工具一

2. Node-RED 流程模擬器 v4［一段 01:02–08:00］

  • 不是只有模擬。可以真的拉 inject、function、debug 節點，可以拉線，可以在裡面寫程式，然後觸發、單步執行、隨時停在某一步
  • 可以匯入你自己的 Node-RED 流程，老師當場拉了一個 AQI 空品的流程進來，跑出真實資料
  • 可以安裝新節點，包含他自己開發的節點，之後 AI 解析也能認得
  • AI 解析要接 API Key：Groq 負責文字解析，Gemini 負責畫圖。Gemini 是付費的，他當時查到約一個月 420 元
💡
他當場冒出的一個念頭，值得學。畫示意圖要付費，他馬上想到替代方案：「所以益師傅打算說，在這個地方是不是能夠產生一個示意圖的 Markdown 的 Mermaid？你可以在 Mermaid 裡頭畫圖就不用錢了。我再改一下⋯⋯到時候你們就不用在上面畫，就浪費錢。」
看到成本就想替代路徑，這是做工具的人跟只會用工具的人的差別。
🎯
為什麼一堂 AI 課要教 Node-RED？老師講得很清楚：
「學這個你會覺得有點辛苦對不對？但是問題是當你會這些東西之後，你內心裡有一些流程的概念，你未來在學 Codex、或是 Claude Code、或是 N8N 這種 AI Agent 的部分，基本上你都可以克服了。因為 Node-RED 都懂了，基本上這些沒有所不懂的道理。」
換句話說：Node-RED 是流程思維的前置訓練。先在看得見的節點與連線上把流程想清楚，之後面對 Agent 就不會卡在觀念上。

  • 每個元件都給：逐層結構、原始示意圖、電氣特性、接腳圖
  • 可 360 度旋轉、拉大層間距，做成 3D 爆炸圖動態展示
  • 做了英文版可切換。老師的說法是「益師傅的企圖心很大，要送給國際的友人」

📦
這個工具的來歷有點感性。他說那天在整理自己的零件庫，「哇，裡頭好多好多的這種感測元件，我之前很愛買，裡頭我覺得應該幾十萬有吧」。因為後來沒在做這塊，他打算陸續把實體零件捐給學校，而這套 3D 圖就是把那段經歷留下來的方式：「假如至少代表益師傅曾經走過物聯網，對不對？」

它比積木程式多了什麼

有學員問這跟積木程式像不像，老師的回答是關鍵：「最大的差別就是它有教學的成分。」

方法拆解

5. 那張 3D 圖是怎麼做出來的［一段 27:05–28:41］

有學員問他 3D 爆炸圖到底怎麼做的，他把整個過程講了一遍。這段是這堂課最值得抄下來的方法論之一。

  1. 先看到別人的成果。他在網路上看到有人用 ChatGPT 的繪圖模型，把晶片封裝一層一層用 3D 做出來，測試 CoWoS 那種堆疊結構的正確性。「一次就成功了，我看到那個東西我就很驚豔」
  2. 把提示詞收起來。「他有一個提示詞，我就給他收起來。」
  3. 自己先試一次。拿那個提示詞在自己的帳號上跑，「發現真的可以畫出那個圖」
  4. 不滿意就講出哪裡不滿意。「但是我就覺得那個圖黑黑的醜醜的，就覺得我不喜歡」
  5. 換成自己的題目，失敗了。「我就跟他講說，好吧，我想改成 ESP32 的結構圖。結果他畫出來不對」
  6. 給它參考物。「我說你可不可以參考我給他看我那個爆炸圖的 Mermaid？給了他，他就幫我畫出來囉」
  7. 再加上風格要求。「我說我要 3D 的高質感、淺色系的。哇，他畫出來有光質感喔」
  8. 找到訣竅就量產。「從那時候我就開始一系列的就這樣做下去了。我把所有的這些元件的 datasheet 給他看。」有些它會弄錯，有些它會自己上網找，就這樣堆疊到 50 組
🔑
這八步可以套到任何你想學的 AI 產出。看到好東西不是收藏就算了，而是：收下提示詞 → 自己跑一次 → 說出不滿意的地方 → 換成自己的題目 → 失敗就給它參考物 → 加上風格描述 → 成功後量產。
整個過程沒有一步需要你會畫圖。
主線一

6. 簡報復刻：讓 AI 學會你的版型［一段 33:36–52:00］

這件事的起點是一個真實提問。老師說：「我上禮拜五在幫一個研習，一個老闆提到說，假如這樣子，會不會我給他一個簡報讓他去學習？」他回去驗證，答案是可以。

用 Codex 做的完整步驟

  1. 專案 → 按加 → 命名（例如「簡報版型風格複製」）
  2. 指定資料夾，選一個你固定放東西的位置。老師當場示範了反例：他第一次沒指定，加上名字重複，結果整個錯亂，只好全部刪掉重來
  3. 到設定 → 一般 → 打開「完整存取權」。不打開的話它每做一個動作都會回來問你，「停下來你也去忙別的事情，你就沒有注意到你要按下一步」
  4. 把要當範本的 PowerPoint 複製到那個資料夾
  5. 開新對話，貼上提示詞，把裡面的檔名改成你自己資料夾裡的檔名（它會去資料夾裡找這個檔案）
  6. 送出，等它跑
⚠️
一個很容易踩的坑：跳出來的風格建議，一個都不要選。
「當它出現這個風格的時候，你都不要選。你都不要選喔，真的，你只要選了之後，它會以它的風格為主。你就千萬不要選，你就不要管它。」
因為你要的是「學會你給的版型」，不是「用它推薦的漂亮版型」。

結果：花 16 分 27 秒，做出 20 頁

他驗證的方式很實在：把原始版型跟產出並排、都切成格狀縮圖，一頁一頁對。字體、大字體、版面結構、曲線圖位置都對得上。

🔍
注意那份回報裡的兩個細節：它自己做了溢位與版型忠實度檢查，還留下一份偏差紀錄檔，並主動說明「未使用 imagegen，因原範本圖像元素已足夠」。
這就是下一章要講的，Agent 跟聊天最大的差別：它會回頭檢查自己做得對不對。
📌
可以套什麼資料？老師舉的例子很生活：你公司之前用的匯報簡報、會議紀錄的簡報，甚至把會議紀錄的 MP3 餵給它。「他會去學這 20 頁的風格」，再用簡報功能做出來。
主線二 · 這堂的核心

7. 把流程變成參數化的 Skill［一段 53:13–65:50］

做成功了，然後呢？大部分人到這裡就結束了。老師沒有。

第一步：請 AI 把剛剛做的事寫成 Skill

他的動機很實際：「並不是每一個人都會去用 Codex。那假如在 ChatGPT 你有付費、但是你沒有用 Codex 的人，一樣可以做，那不是很好嗎？」

💬
他對 AI 說的話大意是：「請你幫我生成一個 Skill，幫我把剛剛的動作做成一個 Skill，並且提供一個 Markdown 的語法讓我下載。」
結果拿到一份很長的提示詞檔。他自己笑說：「你會發現這個提示詞一看就知道不是我寫的。」

第二步：Skill 不是綁在一個平台上的

🔓
「有這個 Skill 檔，你可以放在你的 Claude 裡頭用，或是 Perplexity 一樣可以把 Skill 加進來。」
那 ChatGPT 呢？「當然是可以的。」
他接著講了一段很到位的話：「因為沒有人告訴你不能這樣子用啊。大家好像就是覺得 Skill 就是 Skill，不能用在別的地方。沒有這道理啦。任何地方都可以用。畢竟它只是一個提示詞，它只是一個 prompt。」
唯一的例外他也講清楚了：「除非裡頭有提到串接的運用⋯⋯串接就沒辦法。只是單純它只是一個描述、去取出它的特色來講的話，你當提示詞都可以用。」
  1. ChatGPT 專案 → 加 → 命名 → 建立
  2. 點中央（或右上三個點）進到指令，把整份 Skill 內容貼進去，儲存
  3. 到資料來源，上傳你要它學的版型檔。可以放很多份：風格一、風格二、風格三，或是對 A 廠商、B 廠商、C 廠商的不同簡報
⚠️
ChatGPT 這條路有個限制老師講得很白：沒訂閱的話「你要畫圖它最多又只 13 張就不太畫了，而且它最後會把所有的圖片都集中在一頁裡頭，這就不是你要的」。所以這條路比較適合有訂閱的人。

第三步：最關鍵的一句話

「請將上面所有完成的事項做成一個 Skill，但是這個 Skill 能夠根據使用者提供的任何的版型資料⋯⋯來幫我完成上傳資料的復刻運用。

它就變成都是參數了，而不是固定就只能用哪一個檔案。你一定要變成參數。」
［一段 64:25–65:02］做出來的 Skill 從此吃「版型.pptx」這個參數，換任何版型、任何資料都能跑。
🧩
為什麼這一步這麼重要？
沒參數化的 Skill：只能復刻那一個檔案，換一份版型就要重寫。
參數化之後：它變成一個能力，你給它任何版型加任何資料，它都照做。
老師最後說：「所以你知道為什麼益師傅那個 Skill 嗎？就是我這樣講，它幫我做出來的。」他自己的 Skill 庫，就是這樣一個一個長出來的。
驗證

8. 跨平台實測：哪個行、哪個不行［二段 01:29–15:45］

他沒有只講「應該可以」，而是當場帶全班一起測。

平台結果
Codex✅ 成功。老師的主力做法
ChatGPT 專案✅ 成功。適合有訂閱但不熟 Codex 的人，做好還能分享給別人用
Claude Code✅ 學員當場測成功
Gemini Anti-gravity✅ 學員當場測成功
Gemini（聊天）❌ 風格對不上。「它雖然都做出來了，但這個跟我要的風格完全都不同。雖然也很標準，但是這個不符合我的需求」
✅
學員回報成功之後，老師的反應是：「還好你幫我試，這樣就代表 OK⋯⋯所以代表這個概念是成功的，代表這個概念是可行的。」
他也公開道謝：「感謝剛剛的分享，模型選對了就沒有問題。」
把驗證分散給全班做，是一種很聰明的教學方式：既確認了方法通用，也讓每個人真的動手。
成本

9. 模型選擇的經濟學［二段 00:00–01:14 · 13:38–15:20］

他一開始用「超高」推理跑，結果跑完之後做了一件事：降一級再跑一次，看結果一不一樣。

💰
「我現在這次改成高，剛剛是超高嘛。假如高可以達到一樣的效果，那就不要花那麼多錢。」
驗證結果：「高就可以了，不用寫到超高。」
學員之前用「中」也成功過。所以實際結論是：這個任務用中到高就夠，超高是浪費。
🧪
這是一個很少人做但很值得養成的習慣：成功之後往下降一級再試一次，找出「剛好夠用」的那一檔。做一次的差別不大，做一百次就是明顯的成本差距。
實戰

10. Skill 實戰：拆書與爆炸圖［二段 01:45–08:10］

  • 安裝好之後，打 斜線 就會跳出可用的 Skill 清單
  • 選 PDF 拆分，然後什麼都不用說，直接把 PDF 丟進去送出
  • 爆炸圖那支他做成全域的，「在任何專案裡頭都可以做這樣的運用」，以後只要把圖丟進來就能直接呼叫
⚖️
他很誠實地講了 Skill 版的缺點。同一件事他先前已經寫過一支網頁工具：
「但是我給你那個程式更快，對不對？還不用耗點數。」
Skill 版要扣 AI 的點數，網頁版免費而且更快。他建議「你自己評估在哪邊做會比較方便」。
那 Skill 版的優勢在哪？在於它可以接下一步：拆完可以直接寄 Mail 給你，或串到 NotebookLM 做成 Podcast。單機工具做不到這件事。
觀念

11. Agent 跟聊天寫程式差在哪［二段 06:07–07:00］

有人問他，在 Claude 或 Gemini 的聊天視窗寫程式，跟用 AI Agent 寫，差別到底在哪。他的答案很具體。

🔁
「同樣的提示詞，我上次不是有試給大家看，同樣一個彈珠台，在 Claude 裡頭 chat、就是聊天的方式，他去寫，他寫出來的效果還不錯。」
所以簡單的東西，聊天就夠了。差別出現在複雜的時候：
「假如你今天是屬於程序上比較複雜的，你用 AI Agent 來做有一個好處，他會去檢視自己，他會去檢視自己到底哪一段有問題。」
他舉的例子很好懂：「我說請他幫我順便上架，他會去檢查說他的上架結果，他自己預覽效果好不好。可是我們自己開發程式卻不會有這樣的一個狀況。可是 AI Agent 他卻可以幫你做這個事情。」
🔗
把這段跟第 6 章那份完成回報放在一起看就懂了：那句「通過 20 頁渲染、溢位與版型忠實度檢查」跟那份 deviation-log.txt，就是「它會去檢視自己」的具體長相。
你不用相信它做對了，因為它自己會回頭看，而且把看的結果留下來給你查。
圖像

12. 七種風格：怎麼讓它真的畫圖［二段 08:11–23:30］

三個讓它乖乖畫圖的訣竅

  1. 一次講完要幾張。「跟他講說 1 到 7 請個別畫出圖像，不然他會問你，他會問你說你到底要什麼，很浪費時間」
  2. 指定編號時要補「請畫出圖像」。「你要 3 的話，你不要只有輸入 3。我發現在 Gemini 或 ChatGPT，他會寫出一大堆提示詞，他就是不畫，你要跟他講『再畫出圖像』，又浪費一次」
  3. 專案設定裡務必勾「創作圖像」。老師連講三次「務必」，不勾它就不會畫
👀
一個很好的順手學習示範。他說 AI 在過程中「無意中給我他的程式的語法，Python 的程式的語法，怎麼樣去控制他的位置」，他的反應是：「哦，好，那我又學起來了。就把這個東西給學起來了。」
AI 吐出來的中間過程往往比最終答案更有料，看到就收下來。
  • 用 Gemini 3.1 Flash Lite Image，十幾秒一張，一張約 1 元
  • 解析度最高 1024×1024。老師的評估：「就一般的教學，或是所謂的一些社群文案貼圖的部分，你當都是夠」
  • 要生圖就是要付費，他講得直接：「你說可是這個東西不是就是要花錢嗎？答案是的」
工具四

13. Podcast 提示詞產生器［二段 24:44–50:30］

這支不產生 Podcast，它產生的是給 NotebookLM 用的提示詞。老師解釋差別：「這邊比較快，這邊可以生成你要的提示詞能用。」

可以設定什麼

項目選項
聽眾對象初學者、一般大眾、專業人士、主管或投資人
敘事節奏漸進式、先高後穩、上上下下
主持人自己命名（他當場設「益師傅」跟「小美人」）、選性別、寫風格
要不要自我介紹要的話它會講自己是做什麼的
時間長度20 分或更長
對談風格輕鬆對談、辯論交鋒等四種
必提關鍵字一定要提到的東西，「他還是會提到關鍵字」
禁止提及不得出現的主題，例如品牌名稱、政治立場
額外要求繁體中文、口語化、幽默、引用數據、預告下集、互動提問
⚔️
「辯論交鋒」這個選項，老師特別推薦，理由很值得記。
「假如你要探索一個主題，我都建議選辯論。假如你想要探索一個文案、你自己寫的資料，你不確定到底好或不好⋯⋯麻煩你做一份叫做辯論，另外一個會站在反對方來看你相關文件的資料。
這樣很好啊。有時候因為 LLM 被我們訓練，他訓練出來都是講好話。你可以勾選辯論，讓他站在不同的觀點來看這件事情。」
用機制對抗 AI 的討好傾向，這比提醒自己「要保持懷疑」有效得多。
🎧
互動提問是什麼？他解釋了那個你可能聽過但沒注意的細節：NotebookLM 的語音摘要「最後是不是會留待幾個問題跟你們探索互動⋯⋯他就會出幾個問題」。那個效果就是從這個設定來的。

一個順手的小技巧：把圖片塞進單檔工具

🖼️
老師問大家有沒有發現頁面上那張圖在上下輕微飄動。做法是：
「你就丟一張圖跟他講，你要去背，並且把這個圖透過 base64 直接給塞進去，他就幫你做好囉，他就幫你做在你的程式裡頭。」
「所以你的程式都永遠不用擔心只能用那些 emoji 的小圖，你也可以做一些漂亮的圖放在裡頭。」
他的完整流程是：網路上找圖 → 用 ChatGPT 轉成向量圖 → 改顏色 → 做成最終圖 → 丟給 AI 說「幫我去背、放右上角、要有微微飄動的感覺」。
然後他下了一句結論：「全部都用講的。全部都腦袋有想法，你用講的把它講出來，他自然就可以幫你做。」
現場

14. 現場的真實

他做到一半發現自己想太多

🕳️
講 Podcast 工具時，他一路加功能：試聽、換聲音、下載字幕、下載 MP4。講到後面自己停下來：
「我乾脆講，連那個聲音都不用 copy，然後下拉，他自己內定拿幾種聲音可以選擇，這樣不更棒⋯⋯你看，層次就是這樣一直改過。改一改，我幹嘛挖一個坑給自己跳？」
後來他還問全班：「你們覺得要這樣做嗎？有需要這樣做嗎？」沒人回應，他就說「那就先不做吧，你們就直接用到 NotebookLM 裡頭來做就好了」。
知道什麼不該做，跟知道什麼該做一樣重要。他最後也講了那個技術上的真正原因：NotebookLM 可以用很少的資料生成一二十分鐘的內容，「它內容會直接去填充、去把它給強化」，自己重做這段反而更麻煩。

他也會找不到自己的檔案

示範圖像工具時，他連續給錯版本，翻了好幾次日期才確認：「不好意思，我這個再整理一下給大家好不好⋯⋯我搞錯了，我是要給你們另外一個程式。」跟他在其他堂課遇到的狀況一樣，同時開很多專案、每支又改很多版，版本管理本身就是個問題。

他反覆測到有把握才敢講

🧪
「我就一直反覆測這個東西了。確定到這個提示詞是 OK 的、沒有問題，才敢跟大家分享。」
這句話值得放在心上：他給學員的每一段提示詞，背後都有一輪自己先撞過的牆。
