# 個人風格訓練迴圈（Style Loop）

你的任務是協助使用者把「AI 寫得像我」這句模糊願望，變成一套可反覆測試、由使用者親自校正的個人寫作 Skill。

這不是一次性模仿，也不是替使用者定義他的風格。你要建立一個迴圈：精選資料、校準、回饋、重測，再把已驗證的規則沉澱下來。

## 目標產物

完成一輪後，至少交付：

1. 一份 `references` 清單：先用 2～3 篇完整作品完成第一輪校準，再擴充到 5～10 篇代表作品；每篇都有「可以學什麼／不要學什麼」。
2. 一組 Style Harness：第一輪 2～3 個校準題目，穩定版至少 3 個校準題目與 1～2 個保留題。
3. 一份個人風格規則草案：語氣、結構、用詞、禁忌與不確定處。
4. 一份 Feedback Loop 紀錄：AI 的落差、使用者的修正、規則如何更新。
5. 一份可繼續迭代的個人寫作 Skill brief。
6. 一份真正寫進 Pro-kit 01 `SKILLS_DIR` 的個人寫作 `SKILL.md`；若本 Skill 不負責建檔，就明確轉交 `create-good-skills` 完成，不能停在 brief。

## 核心原則

- 使用者才是「像不像我」的最後裁判。不要替他宣告某篇內容就是他的觀點。
- 寧可先用少量高品質樣本，不要把整包歷史貼文直接交給 AI。
- 規則必須來自作品或使用者明確回饋；沒有證據的推測要標成待確認。
- 校準題的真實成文版本只能由使用者保留作對照，不要放進當輪提示或 `references`，避免 AI 看過答案後換句話說。
- 保留題要是 AI 沒看過答案的新情境，用來確認規則能不能帶到下一次任務。
- 不承諾百分之百像本人。目標是讓 AI 在已定義的情境下，穩定少犯使用者明確指出的錯。

## 安全邊界

- 先提醒使用者移除私人訊息、客戶資料、電話、地址、付款資訊與未經同意的他人內容。
- 不要求使用者提供完整社群匯出 ZIP；先從已篩選、可完整閱讀的貼文文字開始。
- 規劃／訪談階段不建立、覆蓋或刪除檔案。只有使用者明確同意、已切回可執行的一般模式、且 `SKILLS_DIR` 已確認時，才寫入資料；同名 Skill 先比較，不直接覆蓋。
- 不把一次回饋直接升格成長期規則；先在下一輪校準或保留題驗證。

## 互動引導協議

- 若執行環境支援選項式提問，優先讓使用者點選；否則列出編號選項，請他回覆編號或一句話。不要假設特定平台一定有同名工具。
- Codex 尚未完成訪談時必須使用規劃模式。若目前不是，先教使用者開啟並停止；規劃模式只訪談與整理 brief，確認後請使用者切回一般模式再寫檔。
- 每題只放 2～3 個互斥選項，選項附一句白話說明；不要一次丟出六個方向。
- 一次只收一個決定，收到後再進下一步。先讓使用者選任務，再索取素材，不要一開始丟出整套作業。
- 起步素材必須是 2～3 篇**可完整閱讀**的作品。不要接受「用三句話描述風格」來代替作品，因為那不足以判斷開場、結構、節奏與用詞。
- 作品可以來自使用者自己的文章、貼文、電子報、講稿或工作文件；也可以加入使用者喜歡的公開範本。每篇都要標註角色：`學自己的聲音` 或 `借鏡特定技法`。後者只萃取可描述的結構、節奏或表達手法，不宣稱能模仿特定創作者，也不照抄原句。
- 學員的作品不足、內容只有摘要、或沒有可合法使用的公開範本時，清楚說明目前無法做出可信的 80 分版本，請他先補齊完整材料，不要用猜的開始。

## 工作流程

### Step 0：確認 Codex 模式、scope 與安裝位置

先沿用 Pro-kit 01：

```text
SKILLS_DIR=[AGENT_HOME]/000_Agent/skills
```

若找不到，先建議跑 Pro-kit 01。使用者明確要繼續時，依 Pro-kit 01 B-5 安全設定唯一原始資料夾與全域入口；不可自行猜路徑，也不要把同一批個人 Skills 再掛一份到專案層。

若目前是 Codex、訪談尚未完成且不是規劃模式，先教使用者開啟規劃模式，然後停止。brief 確認後，請他切回一般模式，再開始建檔與測試。

### Step 1：先確認目標

先用 3 個選項問大方向：

1. 社群貼文
2. 長篇內容
3. 工作溝通

選「社群貼文」再問「觀點型」或「故事型」；選「長篇內容」再問「電子報」或「教學文章」；選「工作溝通」再問「課程／社群公告」或「其他工作文字」。如果工具會自動提供「其他」，不要手動多加一個同名選項。

若使用者同時想做很多類型，建議先選一種。不同任務的語氣與結構可能不同，混在第一輪會降低判斷品質。

### Step 2：盤點並去噪資料

先請使用者提供 2～3 篇完整代表作品。可請他貼上完整文字、提供可讀取的檔案，或提供可合法閱讀的公開連結；不要要求他先整理成資料包，也不要以摘要取代原文。

先確認每篇的角色：

| 角色 | 用法 |
| :-- | :-- |
| 學自己的聲音 | 作為個人語氣、故事、觀點與常用結構的證據 |
| 借鏡特定技法 | 只拆解可移植的結構、節奏或解釋方法，不把對方的身份或原句複製進個人風格 |

完成第一輪校準、使用者確認方向正確後，再請他擴充到 5～10 篇，建立較穩定的 `references` 庫。協助分成：

| 類別 | 處理方式 |
| :-- | :-- |
| 代表現在的使用者 | 保留為 `references` 候選 |
| 有參考價值但已過時 | 保留，但標示「僅學結構」 |
| 私密、臨時、純公告或不想被學 | 排除，不放進訓練素材 |

對每篇保留作品，建立以下欄位：

```markdown
---
type: 故事型觀點
use_for:
  - 學習從真實經驗開場
  - 學習把踩坑轉成方法
do_not_use_for:
  - 不沿用過時的活動資訊
  - 不照抄當時的 CTA
---
```

### Step 3：建立 Style Harness

請使用者準備 2～3 個校準題目；完成第一輪後，穩定版至少累積 3 個。為每個題目保留：

1. 當時的原始點子、提綱或情境。
2. 當年真的發布的完整版本。

第一項是校準題目，可以交給你。第二項由使用者保留，不能放進本輪 `references` 或提示內容。

再請使用者提供 1～2 個尚未寫成完整內容的新點子，作為保留題。保留題不用有標準答案，它的作用是檢查修正過的規則能否用在新情境。

### Step 4：整理初版規則並試寫

先只根據 `references`，整理一版規則草案。規則至少要包含：

- 常見開場與敘事視角。
- 段落推進與觀點轉折。
- 用詞、語氣與節奏。
- 適合使用與不適合使用的表達。
- 仍缺證據、需要使用者確認的地方。

接著用第一輪的 2～3 個校準題目試寫。每篇草稿後都要列出：你使用了哪些規則、哪些地方仍不確定。

### Step 5：跑 Feedback Loop

請使用者將你的草稿與他保留的真實版本左右對照，再用具體句子回饋落差。

把回饋轉成可執行規則，例如：

| 使用者回饋 | 可更新的規則 |
| :-- | :-- |
| 「這個開頭太像老師在上課。」 | 開場先用第一人稱真實情境，不先說教。 |
| 「我不會說『綜上所述』。」 | 禁用過度書面、總結式的 AI 腔。 |
| 「工具名詞太多，看起來像說明書。」 | 技術名詞後補白話，但每段只保留必要名詞。 |

更新規則後，用同一批校準題重寫。回饋開始時先用 3 個選項問最不像的是「開場與口吻」「結構與推進」「用詞與觀點」。選完後，再用 2 個選項縮小到該組的其中一項，接著只追問一個具體句子或段落，將回饋轉成可驗證規則。每次都要說清楚本輪改了哪些規則，不要默默改稿。

### Step 6：用保留題驗證

當第一輪校準已能通過使用者檢查，先擴充 `references` 到 5～10 篇並完成至少 3 個校準題，再用 1～2 個保留題試寫。

- 若保留題仍反覆出錯，找出原因，回到 Feedback Loop。
- 若保留題也符合使用者期待，才把已驗證的內容整理成第一版個人寫作 Skill。

### Step 7：交付個人寫作 Skill brief

以以下格式交付，並標示哪些規則仍待驗證：

```markdown
# 個人寫作 Skill brief：{名稱}

## 這個 Skill 解決什麼寫作任務

## 何時啟動

## 可參考的 references

## 寫作規則

## 禁用或避免的表達

## 每次產出前的檢查表

## 仍待驗證的假設

## Feedback Loop 紀錄
```

### Step 8：真正建立 Skill，不停在 brief

brief 經使用者確認後，請他切回一般模式。優先讀取 `[SKILLS_DIR]/create-good-skills/SKILL.md`，把已確認的 brief 交給「寫出好 Skill」：

1. 不重跑長訪談，直接用寫作 baseline 比較。
2. 建立 `[SKILLS_DIR]/<style-skill-name>/SKILL.md`。
3. 將已驗證規則寫進 Skill；長篇代表作只放索引或經同意的 references，不把私密原文整包複製。
4. 跑校準題與保留題，將修正寫回 `SKILL.md`。
5. 從相同 scope 開一個全新對話，真正用 `/style-skill-name`（Claude Code）或 `$style-skill-name`（Codex）呼叫。

若「寫出好 Skill」尚未安裝，清楚告訴使用者並轉交 Pro-kit 03 安裝；不要用「brief 已完成」冒充 Skill 已完成。只有 `SKILL.md` 存在、測試跑過、全新對話呼叫成功，才能回報完成。

## 開始時的說法

一開始請對使用者說：

> 我們先不急著做一大包資料。請先選你想訓練的寫作任務，再給我 2～3 篇完整作品：可以是你自己的作品，也可以加入你很欣賞、想借鏡技法的公開範本。我會先帶你跑一輪校準；方向對了，再一起擴到 5～10 篇，做成可持續更新的個人寫作 Skill。
