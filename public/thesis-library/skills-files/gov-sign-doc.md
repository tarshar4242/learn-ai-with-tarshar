# 公文簽產生器（gov-sign-doc）

## 什麼時候用

使用者丟出**機關內部要陳核的事由**（附會議紀錄、來函、勘查紀錄、廠商報價等），要把它寫成一份可以送簽的「簽」時使用。

不適用：對外行文的「函」、開會通知單、便箋、獎懲令——那些是另一種公文類別，格式不同。使用者若要的是「函」，先確認再做。

---

## 鐵則三條（違反就是做壞）

### 1. 來源文件沒寫的，一個字都不能自己編

這是本技能存在的主要理由。曾經發生的錯誤：抄別案範本，替使用者憑空補上「252一般房屋修護費」「檢陳議價須知等採購文件」「附件2變更設計預算書」，而那些在她的來源文件裡根本不存在，送出去會被會辦單位退。

**做法**：
- 來源文件**逐頁看完**（PDF 用 `pdfinfo` 核對頁數，掃描件要一頁一頁看圖，不能只抽文字層）
- 每一句黑字都要能指回來源文件的某一頁某一欄
- 引不到來源的內容 → **一律紅字**，並在紅字裡寫明「本項○○紀錄未載，須由承辦人確認後填列」
- 待填數字、金額、名稱 → 紅色空白底線欄位，不要自己猜長度以外的東西

### 2. 動手前先問齊（見下節六問）

問完才寫。少問一項，後面就要整份重做。

### 3. 每次固定交兩版

同一份事由，**詳細版**與**重點摘要版**各一份 Word 檔，一起交付。不要問她要哪一版，兩版都給，讓她挑。

## 動手前必問的六件事

用 AskUserQuestion 或直接條列問，**問完才動筆**：

| # | 要問什麼 | 為什麼要問 |
|---|---|---|
| 1 | **這份簽要以哪個單位、哪個人的名義簽發？** | 「簽　於　○○○」那一行，猜錯整份作廢 |
| 2 | **來源文件是哪幾份？有沒有漏給？** | 例：只給第4次會議紀錄，但第5、6次另有新增事項；沒問就會漏項 |
| 3 | **要辦的事情定性為什麼？**（契約變更／請購／經費支應／陳報備查…） | 決定主旨怎麼寫、擬辦怎麼收尾 |
| 4 | **金額、數量、預算科目已經確定了嗎？**（有的話請提供；沒有就留空） | 沒確定就全部留紅字空白，不可引用他案數字 |
| 5 | **有沒有既有的簽範本可以參考？**（同機關前案最好） | 各機關批核欄位、期望語習慣不同 |
| 6 | **附件實際會附哪幾份？**（只列真的會放進附件袋的） | 列了不存在的附件會被退件 |

若使用者說「你自己判斷」，仍要把判斷結果寫進交付說明，讓她複核。

## 簽的規範格式（文書處理手冊）

### 基本結構：三段式

**主旨 → 說明 → 擬辦**。可視情形只用一段或兩段完成，但**用了就要按順序**，不可跳段。

- **主旨**：全案精要，**一段完成，不分項**，最後結以期望語。
  - 期望語：陳核用「請鑒核」「請核示」「請核准」；陳報用「請鑒察」「請查照」。
  - 句型：`有關（本分署）「○○○○」○○一案，請鑒核。`
- **說明**：主旨無法容納的事實、來源、經過、理由。分項標號「一、二、三…」，第二層「（一）（二）」，第三層「1、2、3」。
  - 第一項固定寫**依據**：`依○○○115年○月○日○○會議紀錄（附件1）辦理。`
  - 其後依事理先後或輕重緩急排列，**一項一事**。
- **擬辦**：向上級提出的具體處理意見或解決方案。分項標號同上。
  - 沒有具體建議可提時，寧可不寫擬辦，也不要寫空話。

### 版面規格

| 項目 | 規格 |
|---|---|
| 紙張 | A4 直式，由左至右橫書 |
| 字體 | 標楷體（本文 12pt／附註 11pt） |
| 行距 | 固定行高，段落之間留空 |
| 首欄 | 右上角：檔　號／保存年限／日　期（均留空白底線給承辦填） |
| 標題行 | 左側：`簽　　於　　○○○○`（單位名稱） |
| 分項縮排 | 主旨/說明/擬辦頂格；一、二、三 縮1字；（一）（二）縮2字；1、2、3 縮3字。**採首行凸排**，第二行對齊第一行文字起點 |
| 附件 | 正文後另列「附件1：…」，一份一行 |
| 批核欄 | 末段「— 批核軌跡及意見 —」，依機關實際層級列承辦人／主管／會辦／決行 |

### 用語規則

- 一律**第三人稱**、書面語，不用「我們」「你們」
- 慣用語：`爰`（因此）、`俟`（等到）、`旨案`（本案）、`乙節`（這一點）、`前開／上開`（前述）、`檢陳`（附上呈核）、`併知`（一併通知）
- 數字：本文用阿拉伯數字（150日曆天、11.5%）；序號用國字（一、二、三）
- 金額：`新臺幣○○○元整`（用「臺」不用「台」）
- 民國紀年：`115年7月21日`
- 引述他人意見要標明主體：`監造單位建議…`／`主辦機關指示…`／`施工單位反映…`，不可混寫成自己的判斷

## 黑字紅字規則（本技能的核心機制）

| 顏色 | 用途 | 範例 |
|---|---|---|
| **黑字** | 來源文件逐字有的事實 | 「累計使用工期41日曆天，剩餘工期109日曆天」（會議紀錄第3頁） |
| **紅字** | 來源沒有的：待填欄位、建議作法、提醒、推論 | 「【以下為會議紀錄未載事項，須另行確認後填列】…」 |
| **紅色空白底線** | 要她填的數字或名稱 | 金額、計畫名稱、請購單號、承辦人姓名 |

**文件最上方固定加一段紅字使用說明**（列印前刪除）：

> 【使用說明．列印前請刪除本段】黑字＝出自○○○；紅字＝來源文件未記載，須由承辦人確認、補充或刪除後方可送出。

**推論也要標紅**。就算是從來源數字推出來、很合理的判斷（例如「進度超前，研判變更對工期影響有限」），只要不是來源文件寫的結論，就是紅字，並在後面補一句「上開研判係就○○數據所為之推論，非○○所載結論」。

**發現來源文件本身有錯，也用紅字提醒**，不要默默改。例：會議紀錄表頭誤植次別、日期與封面不符、金額前後不一致。

## 兩版的差別

| | **詳細版** | **重點摘要版** |
|---|---|---|
| 說明段寫法 | 依變更／事由**分類歸納**，每類寫清楚現況、原因、研判依據，約150～200字一段 | **短句條列**，一條一事，只講「改什麼」不講來龍去脈 |
| 適用時機 | 案情複雜、要說服會辦單位、金額大 | 金額明確、事由單純、要快速核章 |
| 篇幅 | 約2.5～3頁 | 約2頁 |
| 兩版共通 | 主旨、工期進度段、金額段、經費段、擬辦、附件、批核欄——**內容一致**，只有說明段的密度不同 | |

**兩版的事實必須完全一致**。摘要版是把詳細版壓縮，不是另寫一份；不可以摘要版有的事詳細版沒有。

## 執行流程

1. **問齊六件事**（上節），使用者回答前不動筆。
2. **逐頁讀完所有來源文件**。
   - `pdfinfo` 核對真實頁數
   - 掃描件用 `pdftoppm -png -r 220` 轉圖後逐張看；直式表格頁若旋轉，看不清楚就提高解析度重轉
   - 多份文件要**互相比對**：哪些事項相同、哪些是後面幾次新增的、數字有沒有更新
3. **列一張對照清單**（自己用，不必交付）：`內容 → 來源第幾頁第幾欄 → 黑字或紅字`。
4. **產出兩版 Word 檔**，用 `assets/build_sign.js` 的寫法（docx npm 套件；紅字 `color: "FF0000"`；空白底線 `underline` + 全形空格）。
5. **驗證**：解開 docx 讀 `word/document.xml`，把每段文字連同紅字／底線標記印出來核對一遍。
   - 本環境的 LibreOffice 常無法轉 PDF，**若轉不出來就據實告訴她「版面沒能親眼確認」**，不要說「已檢查版面」。
6. **交付**：兩份 docx 用 SendUserFile 傳給她，並在同一則訊息說明：
   - 這一版跟上一版改了什麼
   - 哪些地方是紅字、為什麼
   - 有沒有發現來源文件的錯誤
   - 還缺什麼資料才能送出

## 交付前檢查表

- [ ] 六件事都問過了，沒有自行假設
- [ ] 每一句黑字都指得回來源文件
- [ ] 來源沒有的內容全部是紅字，沒有漏網的
- [ ] 待填數字都是紅色空白底線，沒有留 `＿＿＿` 這種手打符號
- [ ] 主旨一段到底、沒分項、結有期望語
- [ ] 說明第一項是依據
- [ ] 分項標號層次正確（一、→（一）→1、）
- [ ] 附件只列真的會附的
- [ ] 兩版事實一致，只有密度不同
- [ ] 文件最上方有紅字使用說明
- [ ] 字體標楷體、A4、首行凸排
- [ ] 檔名含案名與版別，例：`○○工程_第1次契約變更簽陳_詳細版.docx`

## 常見錯誤（都真的發生過）

| 錯誤 | 正確做法 |
|---|---|
| 抄別案的預算科目、法條、附件清單 | 一律紅字留空，請她填 |
| 只看使用者最先給的那一份文件 | 先問「還有沒有其他期別／後續文件」 |
| 把「持續列管」的事項全當成要變更的 | 看主辦機關辦理情形欄的實際批示用語，「納入契約變更」與「配合需求調整」是兩回事 |
| 列管表以外的內容不看 | 「建議及協辦事項」「主辦機關指示事項」常有列管表沒有的新增事項 |
| 沒發現來源文件自己寫錯 | 逐頁比對封面、簽到單、內頁表頭的次別與日期 |
| 說「已檢查版面」但其實沒轉出 PDF | 據實說明未能驗證版面 |
| 只交一版 | 固定交兩版 |
