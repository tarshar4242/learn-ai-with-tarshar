# 用 Tarshar 的風格寫提案

## 這個 Skill 在做什麼

Tarshar 寫提案有一套穩定的樣子：從自己親眼看到的場景切進去，把問題拆層，借幾個具名理論當座標，造一個自己的詞來承載主張，最後收在一個具象比喻上然後停。

這套規則是 2026-08-07 用她的三篇真實作品跑「風格訓練迴圈」萃取出來的，經過校準題五輪與保留題驗證。**不是憑印象猜的，每一條都有作品出處。**

## 使用時機

要寫「說服某個對象採取行動」的正式文件：

- 職場建言書（向主管提出改善建議）
- 專案提案書（向公司提出計畫與預算）
- 課程提案（向機關、企業、學校提出開課方案）
- 合作提案（向合作方說明做法與分工）

## 不適用情境

| 看起來很像 | 其實該用 |
| :-- | :-- |
| 要寫 FB 貼文、Threads | 她的社群風格是另一套，這份不適用 |
| 要寫電子報、行銷文案 | 尚未訓練，不要硬套 |
| 要寫論文、學術文章 | 語域不同，尚未訓練 |
| 只是要把一段文字改得不像 AI | `speak-human-tw` |
| 要整理會議紀錄、做摘要 | 一般任務，不必動用 Skill |

## 必要輸入

開始前一定要問到這四件事，缺了就問，不要猜：

1. **收件人是誰**：主管／機關／客戶／合作方。這決定語域，也決定「誠實寫動搖」那條怎麼寫。
2. **要對方做什麼**：核准、編預算、開課、同意試辦。
3. **對方最可能的疑慮**：資安、成本、人力、責任歸屬。文中要正面回應，不能迴避。
4. **這件事要不要對方編列資源**：要 → 必須寫制度完整度（規模、期程、驗收、KPI、費用）；不要 → 建言書寫法，可以省略。

## 最高原則：點到為止

**這是 Tarshar 最在意的一件事，凌駕以下所有規則。任何規則的執行方式若與它衝突，以它為準。**

- **講完就停。** 不補「這就是說⋯」「也就是⋯」「這代表⋯」。
- **相信讀者接得住。** 不代替讀者下結論，不把話說滿。
- **一個意思講一次。** 不換句話說再講一遍。
- **例子舉一個就夠。** 不堆三個。
- **收尾留白。** 停在具體畫面或比喻上，不要再總結一次。

**點到為止不等於少寫，是濃度要高、話要少。**

兩端都是錯的：
- 太平淡、沒有記憶點 → 濃度不夠
- 每段都補一句解釋 → 話太多，像寫日記

正確位置：每一句都帶新資訊，講到讀者能自己接上為止，然後停。

## 寫作規則

### 核心六條

1. **開場依收件關係選擇姿態**：
   - 對外或平行單位：可從親眼所見的具體場景進入，一個對比講完就收。要有人、有場合、有時間點。
   - 對直屬主管的內部提議：改用「目前常見的狀況」概述，不虛構具體場景，也不以顧問或高層姿態評斷單位。採「謹提供參酌」「如蒙同意」「建議以⋯作為檢視依據」等低姿態表述。
   - 兩者都禁止時代大帽子（「在這個⋯的時代」）。

2. **論述骨架**：現象 → 拆原因 → 質疑現行機制 → 提可執行方案 → **收在人與溝通**。

3. **接上知識座標**：引 2～3 個具名理論或方法論，**行文帶出 ＋ 表格承載**，每個立刻接回現場的具體做法。她的論文線在知識管理，這一區優先。

4. **造一個自明的專有名詞**承載主張，取材自製造業、自然或育成意象，並**畫成一張機制圖**（畫轉換過程，不是畫時程表）。
   - 「自明」是關鍵：「接穗」看到就懂，通過；「去殼」要先解釋稻穀才成立，失敗。

5. **提案類要有制度完整度**：規模、期程、驗收機制、KPI 由誰提出、費用概念。缺一項，對方就無法照著簽。
   - 判準是「對方收到後要不要編列資源」。要，就得寫全；建言書不必。
   - 驗收那一項要正面回應對方的疑慮，不要寫「期末考核」這種空話。

6. **收在一句具象比喻，然後停。**

### 節制三條

7. **講完就停，不補解釋。**（違反就重寫）
   - 禁用思考過程鋪陳：「我一直在想」「後來想起」「仔細想想」。

8. **概念用短語直接給**：「短語＋冒號」或引號短語條列，一行解決一組概念。

9. **一段一個主張。** 不要把層次拆解壓進同一個長段落。

### 個人特徵兩條

10. **指出問題前先肯定動機。**

11. **誠實寫出自己的動搖，再說明被什麼說服。**
    - **對內**（向老闆、同事）：動搖可以放在自己的判斷上。
    - **對外**（向客戶、機關、學員）：動搖放在**制度選擇**上，不要放在自己的專業能力上，否則削弱說服力。

### 格式一條

12. **人名與理論名全篇格式一致**：
    - 人名首次出現：中文譯名 ＋ 半形括號附英文原名，例「薛飛(Yossi Sheffi)」
    - 機構、理論首次出現：中文名 ＋ 半形括號附英文或縮寫，例「麻省理工學院(MIT)」
    - 括號內是中文時改用全形，例「人才的定期保養（面談溝通）」
    - 專有名詞用「」
    - 第二次以後只用中文簡稱
    - **中文與英文、數字相鄰處要有一個半形空格**：「AI 技術」「每班 20 人」

### 禁用兩條

13. **不用見證式案例收尾**。不要「某某學員從 X 進步到 Y，他說⋯」這種前後對照加原話引用。

14. **不用編號當段落標題**。不要「一、羅傑斯的創新擴散理論⋯」，也不要「第一步是共同化。第二步是外化。」理論用行文帶出或收進表格。

### 待驗證兩條（可用，但用了要跟她說）

- **反直覺重新歸因**：把矛頭從常見嫌疑犯移到真兇，當標題與全文主軸。例：「AI 不是問題，你交辦任務的方式才是」
- **收尾前先鋪陳讀者的下一個卡點**：三到四個具體問題，用讀者的口吻寫（「我到底該⋯？」）。適用課程提案與對外文件；純內部提案可省略。

## 輸出格式

- 標題用 `類型｜核心對象｜主要成果`，例「課程提案｜AI 入門｜給不能出錯的公務現場」
- 正文 900～1300 字。超過就是話太多。
- 理論用一張表格承載
- 收尾比喻之後放一張純文字機制圖，圖下一行「◎」開頭的圖說
- 繁體中文（台灣），全形標點（人名理論的英文括號除外）

## 停止條件

遇到這些情況停下來問她，不要自己編：

- **不知道收件人是誰**，或不確定是對內還是對外——這決定第 11 條怎麼寫
- **需要具體數字**（人數、預算、期程）而她沒給——不要編一個看起來合理的
- **要引用她的真實經歷或案例**而資料不足——不要代她生產經歷
- **內容涉及前雇主的人名、預算、系統名**——問她要不要去識別化
- 兩條規則互相衝突且無法兼顧（例如要引三個理論又要壓在 900 字內）——說明取捨，請她裁定

## 驗收標準

交稿前逐項自檢，全過才交：

- [ ] 開場符合收件關係：對外／平行單位可用真實場景；對直屬主管只概述常見狀況、不虛構場景，且姿態謙抑
- [ ] **沒有任何一句在解釋前一句**（這條最常違反）
- [ ] 引了 2～3 個具名理論，格式全篇一致
- [ ] 造了一個自明的專有名詞，不需要先解釋別的東西才懂
- [ ] 有機制圖，畫的是轉換過程不是時程表
- [ ] 需要編列資源的話，規模／期程／驗收／KPI／費用五項齊全
- [ ] 收尾停在比喻上，沒有再補一句總結
- [ ] 中英文相鄰處有半形空格
- [ ] 沒有見證式收尾、沒有編號段落標題
- [ ] 正文在 900～1300 字內

**改稿時額外檢查**：對照上一版逐項確認，不得弄丟已經通過的用詞與寫法。改 A 壞 B 是這套流程最常見的坑。

## 跟其他 Skill 的分工

**這份只管「像不像 Tarshar」，不管「像不像 AI 寫的」。**

去 AI 味、台灣用語校正、標點修正交給 `speak-human-tw`。

**順序不可顛倒**：先套個人風格，再用說人話檢查。反過來會把她的聲音洗掉。

## 這仍是早期版本

規則是從三篇作品萃取的，樣本還不多。未來每次她說「這裡不像我」，只修一個最重要的落差，然後用同一題再測一次——不要一次加十條新規則。

上一次就是這樣學到的：規則從 17 條長到 30 條之後，產出反而變差（她的評語是「完全不行，更糟」），精簡回 14 條才通過。**規則變多不等於變好。**
