# Digital Employee Case Cards

Create case-study teaching cards, not generic summary cards.

Default to rich, information-dense cards that look like a full teaching handout rather than a simplified poster.

## Lock the output first

Treat each request as one focused micro-course about a single agent, workflow, or project.

Define these four locks before drafting:

1. Course promise: what the learner should understand or copy.
2. Core question: what operating problem the case solves.
3. Teaching boundary: what belongs in this case and what must be left out.
4. Learning sequence: the shortest path from background to operation to reusable method.

If the source material contains multiple threads, prioritize the line that explains how the digital employee works and why the method is reusable.

## Default deliverable

Unless the user overrides it, produce:

1. One main cover card.
2. A-series, modern digital employee, four cards.
3. B-series, case-study teaching, four cards.

Keep the facts identical across A and B. Only the visual teaching angle changes.

## Never drift into these formats

Do not produce:

- summary cards that evenly paraphrase the source;
- course sales posters or registration graphics;
- motivational quote cards;
- sparse title-only cards with no instructional structure;
- simplified or thin cards that flatten the case into a few slogans;
- mascot treatment that pastes the same photo repeatedly.

If the user provides thread-specific reference cards, match their density and chibi style first. Do not quietly switch back to a lighter or cleaner internal style.

If the user says「整理圖卡」without extra detail and the source sounds like an agent/project case, assume they want the case-study lesson-card mode.

## Required structure

### Cover card

State:

- the case name;
- what this digital employee does;
- why the case matters;
- the two teaching angles: digital employee view and teaching breakdown view.

### A-series: modern digital employee

Use the subtitle `數位員工履歷風`.

Default sequence:

1. `A01 角色定位`
Explain who the agent is, what role it plays, what scope it owns, and what outcome it is responsible for.

2. `A02 任務交辦`
Show the handoff format, input material, decision boundary, and what the user needs to provide.

3. `A03 增量同步`
Show how the agent checks existing materials, keeps prior content, adds only new material, and avoids destructive replacement.

4. `A04 驗證交付`
Show how the agent checks correctness, confirms outputs, archives results, and updates the visible master record when relevant.

### B-series: case-study teaching

Use the subtitle `案例拆解教學風`.

Default sequence:

1. `B01 需求與轉捩點`
Explain the original pain, why the old way failed, and what changed.

2. `B02 修正歷程`
Show the main wrong turns, prompt corrections, structure adjustments, and what improved the output.

3. `B03 自動工作循環`
Explain the loop clearly: intake, compare, add only increment, verify, archive, update table, report back.

4. `B04 可複製教學`
Turn the case into a reusable method, prompt pattern, or operational checklist.

## Required content emphasis

Make these ideas explicit whenever they are true in the case:

- the agent is the user's digital employee;
- it can work automatically after handoff;
- it checks whether same-name folders or prior files already exist;
- it preserves old material and only adds new material;
- it does not delete prior material unless explicitly instructed;
- it updates the master table or visible record when required;
- the method can be copied into future teaching cases.

Do not hide these points in small copy. They are the teaching highlights.

## Visual and layout rules

Use knowledge-card layouts with visible instructional structure:

- modular blocks;
- arrows or flow lines;
- highlighted decision points;
- compact step labels;
- panels that separate role, input, process, check, and result.

Prefer these extra structures whenever they fit:

- before/after comparison blocks;
- circular or directional workflows;
- highlight strip for the agent's strengths;
- conclusion box;
- explicit labels for automatic actions, judgment boundaries, and verification logic.

Make A-series feel like an operational profile or work record.
Make B-series feel like a teaching breakdown or execution manual.

Do not treat "clean" as "empty." The user prefers cards that are rich, modular, and content-heavy when teaching a real success case.

## Mascot and brand rules

Always include the exact footer:

`🍀Learn AI with Tarshar ｜2026`

Use the user's approved female mascot identity when a mascot appears.
Integrate the mascot into the layout with pose or prop variation. Do not repeat the same pasted portrait mechanically.

If the current conversation contains a newer approved small-D reference image, use that as the primary mascot reference for the task.

## Drafting workflow

Follow this order:

1. Lock the case as one focused course.
2. Write the cover and all A/B card titles first.
3. Draft the key teaching point for each card in one sentence.
4. Check whether each card teaches a distinct stage.
5. Add the operational highlights: auto-work, compare-first, increment-only, preserve-old, verify, archive, update.
6. Generate or assemble the final cards.
7. Run a final QA for logo, mascot, readability, and anti-drift rules.

## QA checklist

Before calling the cards final, confirm:

- this is a case-study lesson-card series, not a summary set;
- A and B both exist unless the user asked for fewer cards;
- each card has a specific job and does not repeat the same summary;
- the digital employee / automatic work / increment logic is visibly taught;
- the exact footer logo is present;
- the mascot is integrated cleanly;
- the layout is dense enough to teach, not just decorate.
- the card feels closer to the user's provided reference cards than to a generic infographic template.
